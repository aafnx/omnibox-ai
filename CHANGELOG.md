# Changelog

## 0.17.0 — 2026-10-07

Первый шаг этапа 1 roadmap — отзывчивый API и статус (F1):

- Ключ API проверяется до обращений к службам и движку. Проверка состояния движка и сбор `/api/status`, включая GPU, выполняются в задачах по запросу вне главного HTTP-потока; холодный кеш и медленный движок не блокируют вход и остальные маршруты панели.
- Одновременные запросы разделяют одну проверку состояния. Результат кешируется на секунду, без таймера и опроса в простое. Начало и завершение операций управления сбрасывают кеш; изменения конфигурации и профилей из CLI также учитываются.
- Запрос с устаревшим состоянием после операции управления не допускается к генерации. Число задач проверки и статуса ограничено; SSE передаётся асинхронным прокси и не удерживает PowerShell-задачу.
- Очередь генераций (F2) остаётся следующим шагом: второй одновременный запрос пока получает 409.

## 0.16.3 — 2026-10-07

- Обновление движка закрывает приём новых запросов к `/v1` сразу, как только начинает ждать текущую генерацию, а не после её окончания. Раньше при непрерывном потоке запросов новые генерации успевали начаться в промежутках, и обновление упиралось в таймаут 2 минуты. Если текущая генерация не закончилась за это время, приём снова открывается.
- Подсказка «Свободно на диске моделей» в форме скачивания показывает диск каталога моделей выбранного движка. Раньше брался первый диск с любыми моделями: при Ollama на C: и PrismML на D: форма GGUF показывала место на C:.

## 0.16.2 — 2026-10-07

Исправления по повторному ревью управления движками:

- Переключение версии движка всегда берёт защиту генерации, даже если движок был остановлен. Раньше параллельный запуск мог поднять движок, клиент — начать генерацию, а обновление перезапускало службу под ней. Пока защита взята, новые запросы к `/v1` не начинаются, а другие операции управления ждут.
- Если при удалении движка не удалось ни удалить службу, ни вернуть `config.json`/`gateway.json`, панель сообщает об ошибке отката и пути к сохранённым копиям (`backups\engine-remove-…`) вместо ложного «Настройки восстановлены». Копии удаляются после успешного удаления или отката; из оставшихся хранятся три последние.

## 0.16.1 — 2026-10-07

Исправления управления движками по результатам ревью:

- Обновление работающего движка больше не прерывает генерацию: перед перезапуском панель запрещает новые запросы и ждёт завершения текущего (до 2 минут), иначе переключение откладывается.
- Установка движка и удаление движка или модели перечитывают `config.json` под замком управления: выбор модели Ollama, сделанный во время скачивания, не теряется.
- Повторная установка удалённого движка восстанавливает его профиль, имя службы, каталог моделей и журналы (например, прежний Bonsai).
- Многотомный GGUF показывается одной моделью, защищается от удаления целиком и удаляется со всеми частями.
- Если при удалении движка не удалось удалить службу, `config.json` и `gateway.json` возвращаются к прежнему состоянию.
- Тест истории выпусков пропускает проверку коммитов в копии исходников без git; служебные скрипты обновления определяют путь PowerShell через `[Environment]::ProcessPath`.

## 0.15.0 — 2026-10-06

- Управление ИИ-движками в **Обновления → ИИ-движки** и командой `ai engine`: список версий PrismML и Ollama с GitHub, обновление до последней, выбор нужной версии, установка движка с нуля (служба Windows с ручным запуском, профиль, запись в `config.json`) и удаление.
- Версии хранятся в `engines\<движок>\<версия>`, файлы проверяются по размеру, контрольной сумме и запуску `--version`. Переход на версию идёт через историю отката: при ошибке запуска возвращается прежняя версия, остановленный движок не запускается.
- При удалении движка модели остаются на диске. Отдельная кнопка **Удалить модель** удаляет GGUF PrismML или модель Ollama; выбранную и нужную для отката модель удалить нельзя.
- В «Месте на диске» учитывается объём скачанных движков; незавершённые распаковки удаляются при очистке.

## 0.13.0 — 2026-10-06

- Сообщения CLI и установщика короче и понятнее: без строк про WinSW, PATH и служебных деталей. Команды называют движок, затем модель: `ai status` выводит «PrismML: работает · API готов» и строку с моделью и контекстом.

- `ai storage` показывает занятое место, `ai storage clean` удаляет устаревшие журналы и временные файлы.

## 0.12.0 — 2026-10-06

- Движок называется в панели **PrismML** — по runtime, а не по модели Bonsai. Служба Windows и ключ в `config.json` остаются `bonsai`, поэтому обновление не трогает службы и настройки. В CLI работают оба имени: `ai start prismml` и `ai start bonsai`.
- Настройки модели — в двух режимах. **Обычный**: модель, контекст, Thinking, размещение, выгрузка после простоя, имя в API. **Продвинутый**: дополнительно память, скорость и сэмплинг. Выбор режима запоминается в браузере.
- На телефоне выбор движка и переключатель режимов стоят друг под другом и не сжимаются.

## 0.11.0 — 2026-10-06

- Настройки модели PrismML как в LM Studio. **Thinking и сэмплинг**: режим размышлений (как в шаблоне, включён, выключен), уровень и лимит размышлений, temperature, top-k, top-p, min-p, штрафы за повторы, максимум токенов ответа, seed. **Память и скорость**: все кванты KV-кеша llama-server, KV-кеш на GPU, потоки CPU, mmap/mlock.
- Пустое поле оставляет значение модели и llama-server и не записывает аргумент, поэтому старые сборки llama-server запускаются как раньше. Параметры клиента в запросе имеют приоритет над значениями панели.
- Квант GGUF (Q4_K_M, IQ3_XXS, PQ2_0…) показан в списке моделей.
- Поля формы настроек выровнены по верху, если подсказки в строке разной длины.

## 0.10.0 — 2026-10-06

- Новая настройка PrismML **Слои MoE в RAM** (`--n-cpu-moe`): эксперты MoE-моделей остаются в оперативной памяти, остальное — на GPU. Так в 16 ГБ VRAM запускаются модели вроде Ornith 1.5 35B-A3B (Q4_K_M ≈ 21 ГБ).
- Карточка движка показывает RAM + VRAM и число слоёв, чьи эксперты остались в RAM.
- Флаг `--cpu-moe`, записанный в профиль вручную, читается как «все эксперты в RAM»; режим RAM · CPU убирает выгрузку экспертов из профиля.
- Инструкция по Ornith 1.5 35B-A3B — в `docs/models.md`.

## 0.9.5 — 2026-10-06

- Единая версия в файле `VERSION`: CLI, панель, обновление, установщик и сборка читают её из одного места.
- Общий манифест пакета `package.psd1` для сборки, установщика и тестов.
- Сборка `dist/` не зависит от окончаний строк в checkout: скрипты Windows упаковываются с CRLF, остальные файлы с LF.
- Единый замок установки: `ai update`, веб-обновление и ручной запуск установщика не выполняются одновременно; второй получает понятный отказ без изменений. На время замены файлов заблокировано управление движками из CLI и панели.
- Транзакционная установка: снимок файлов, настроек, XML-профилей с историей отката, команд служб и правил Firewall; журнал шагов; при ошибке на любом шаге — автоматическое восстановление и запуск панели прежней версии. Прерванная установка или неполный откат повторно откатываются при следующем запуске установщика.
- Проверка сохранения настроек по значениям до запуска панели и после отката (пароль, API key, адреса NAS, настройки API и моделей); история отката и доступ gh — побайтово. Расхождение считается ошибкой установки.
- Веб-обновление использует результат транзакции установщика вместо повторного восстановления.
- CI на GitHub Actions: все наборы тестов на Windows и Linux, проверка `dist/` и реальные тесты Windows-служб (`tests/scm_test.ps1`): SCM start/stop, `Win32_Service.Change`, аварийное завершение дочернего процесса и очистка дерева процессов. Настоящая установка на чистой Windows-машине с принудительными сбоями обновления и проверкой отката (`tests/real_install_test.ps1`).

- Bearer API key: генерация/ротация, hash вместо хранения ключа, режим без авторизации.
- Потоковая пересылка SSE и JSON в фоне; API не запускает остановленные службы.
- Установщик настраивает API-порт/Base URL, сохраняет параметры при обновлении и создаёт Firewall-правило.
- Подключение Jan/Pi по IP или HTTPS через NAS; отдельная инструкция LLM reverse proxy.
- Каталог Hugging Face: поиск, варианты GGUF/размеры, ссылки на авторов и загрузка на ПК; ссылки Ollama/PrismML и быстрые uncensored/abliterated запросы.
- Проверки API-ключей, SSE, доступности панели во время генерации, HTTP-лимитов и метаданных каталога.

## 0.5.0 — 2026-10-06

- Подтверждения установщика только `yes/no` и `y/n`, подсказки `[y/N]`/`[Y/n]`.
- Светлая тема всей панели.
- Выделенное поле OpenAI Base URL для Jan/Pi, Model/API key, выбор модели Ollama; технические адреса скрыты в дополнительном разделе.
- Поддержка HTTPS reverse proxy на NAS: внешний origin, доверенные IP, Secure cookies, проверка Origin и запрет HTTP-повторного использования HTTPS-сессий.
- Мастер/параметры установщика для proxy, сохранение конфигурации при обновлении и инструкция Nginx.
- Проверки прямого и proxy HTTP, поддельных заголовков, downgrade, разных IP клиентов и конфигурации.

## 0.4.0 — 2026-10-06

- Универсальная веб-панель: обзор серверов, модели/настройки, подключение клиентов и журналы.
- Управление запуском, остановкой, загрузкой и выгрузкой; нейтральная команда «Остановить все серверы».
- Контекст, таймаут простоя, настройки GPU/cache/batch PrismML; применение с откатом при ошибке запуска.
- Скачивание моделей Ollama и GGUF на ПК в фоне; управление остаётся доступным.
- Вход по отдельному паролю, PBKDF2, сессии, CSRF/Origin и ограничение попыток входа.
- Единый установщик на ПК настраивает WinSW-службу панели, порт, Firewall и ACL; сохраняет локальные параметры при обновлении.
- Статус не загружает модель, постоянного опроса GPU нет. CLI остаётся для диагностики.
- HTTP-интеграционные тесты с настоящим PowerShell-сервером и тестовым адаптером движков.

## 0.3.0 — 2026-10-05

- Установка непосредственно на ПК через SSH: один скрипт с вопросами о папке, сервере, контексте и запуске.
- Загрузчик для приватного GitHub: маскированный ввод токена с Contents Read, без сохранения токена в файл или PATH.
- Автоматический откат XML после неудачного запуска с новым контекстом; возвращает прежнее состояние выбранной службы.
- `ai restore [backend]`: ручной возврат предыдущих настроек без поиска backup-файлов.
- Один предыдущий XML и проверяемая история; последовательные неприменённые изменения сохраняют исходную точку отката.
- `ai power`: штатная диагностика пробуждения, таймеров и блокировок сна без изменения WoL.
- Интерактивная установка заменяет режим передачи установщика с ноутбука; `-NonInteractive` для установки без вопросов.

## 0.2.0 — 2026-10-05

- Один самодостаточный установочный скрипт: встроенный пакет, SCP/SSH с ноутбука, без GitHub-токена.
- `ai context [backend] [SIZE]`, `ai start/restart --context SIZE`.
- Контекст PrismML и default Ollama меняются через XML с backup и атомарной записью.
- Различаются сохранённые настройки и контекст уже загруженной модели; скрытого перезапуска нет.
- Расширена `ai help`, добавлены примеры контекста.
- PATH-блок для новых SSH-сессий добавляется в профиль PowerShell 7 без замены промпта, с backup.
- Тесты для контекста, сохранности аргументов/XML и профиля.

## 0.1.0 — 2026-10-05

- Единый CLI `ai` для существующих WinSW-служб Bonsai/PrismML и Ollama.
- Эксклюзивное переключение серверов, mutex для параллельных SSH-команд.
- Статус API/контекста/сна/видеопамяти без загрузки Bonsai.
- Чтение журналов WinSW, вывод OpenAI-совместимого endpoint.
- Native passthrough в Ollama с сохранением stdout/stderr/exit code.
- Установщик в PATH, сохранение JSON при обновлении и backup файлов.
- Самодостаточные тесты, русская документация, SSH-установка для приватного репозитория.

Ограничения первой версии: нет API-прокси, установки runtime и изменения параметров моделей.
