# Сетевой OpenAI API для Jan и Pi

С версии 0.6.0 у OmniBox AI есть OpenAI API для клиентов по пути **`/v1` на порту панели — 18090**. Панель использует `/` и `/api/*`, генерация — `/v1/*`. Подключение не требует SSH-туннеля. Встроенные API движков остаются на localhost; шлюз передаёт запросы выбранному движку.

## Установка и настройки

Повтори обычный установщик на ПК. Ответь `y` на **«Включить сетевой OpenAI API для Jan/Pi?»**. Мастер предложит общий порт панели (18090) и Base URL по выбранному IP ПК либо существующему HTTPS origin панели. На текущем ПК это **`http://192.168.1.77:18090/v1`**, через NAS — **`https://llm.fnx.red/v1`**. Движки при этом не запускаются.

На **«Использовать API key?»** ответь `y` для генерации ключа или `n` для режима без ключа. Новый ключ печатается один раз; сохрани его в Bitwarden. Существующий ключ сохраняется при обновлении. На общем порту используется Firewall-правило панели. При выборе дополнительного порта создаётся `omnibox-ai-api` с теми же разрешёнными адресами. Проверка занятости порта выполняется перед запуском службы.

В панели **Подключение → Сетевой OpenAI API** доступны:

- Движок, который обслуживает API: Bonsai/PrismML либо Ollama. Выбор не запускает и не переключает службы автоматически.
- OpenAI Base URL, который копируют клиенты. Этот адрес должен уже вести к порту API через сеть или NAS.
- Флажок **Требовать API key** и **Сгенерировать новый API key**.
- Крупное поле Base URL, имя модели и технический POST endpoint.

Смена ключа немедленно отзывает предыдущий ключ для новых запросов. Уже начавшаяся генерация может закончиться. Hash SHA256 высокоэнтропийного ключа хранится в защищённом `gateway.json`; исходный ключ не сохраняется. Пароль панели и API key независимы. Для повторного показа старого ключа нет функции: при утрате генерируется новый.

Настройки ключа, движка и отображаемого Base URL применяются без перезапуска. Дополнительный порт/включение API меняются установщиком с перезапуском службы панели. Параметры установщика: `-ApiPort`, `-ApiBaseUrl`, `-NoApi`. Отключение API сохраняет настройки движков. Включение ранее отключённого API выполняется интерактивным мастером.

## Настройки клиента

| Поле | Bonsai на текущем ПК |
|---|---|
| Provider | OpenAI-compatible / Custom OpenAI |
| Base URL | `http://192.168.1.77:18090/v1` |
| Model | `bonsai-2-27b` |
| API key | Сгенерированный ключ; пусто, если авторизация отключена |

Если клиент требует непустой ключ при отключённой авторизации, укажи `local`: шлюз игнорирует ключ в этом режиме. Для Ollama сначала выбери и загрузи модель в панели, затем выбери его движком API и укажи имя выбранной модели из карточки. Другие model отклоняются. По одному Base URL обслуживается один выбранный backend; это не автоматический маршрутизатор моделей между движками.

Путь `/chat/completions` не добавляй в поле Base URL: клиент добавляет его сам. Остановленный движок вернёт 503; API не включает Windows-службу. Запрос к работающему движку может загрузить его модель, как обычный запрос к runtime. `Остановить все серверы` оставляет панель/API доступными, но генерация требует ручного запуска движка.

## HTTPS через NAS

Внешний адрес: **`https://llm.fnx.red/v1`**, без номера порта. Существующее правило **`llm.fnx.red` → `http://192.168.1.77:18090`** подходит и для панели, и для API. На сервере запросы `/v1/*` поступают шлюзу OpenAI, а остальные пути — панели. DNS, сертификат и целевой порт NAS менять не требуется.

Пример location внутри уже настроенного HTTPS server `llm.fnx.red` на NAS:

```nginx
location / {
    proxy_pass http://192.168.1.77:18090;
    proxy_http_version 1.1;
    proxy_set_header Host $proxy_host;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Authorization $http_authorization;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1800s;
    proxy_send_timeout 1800s;
}
```

Существующее проксирование всего корня сохраняет `/v1/...`. NAS должен передавать Authorization, чтобы работал API key; отключение buffering позволяет получать SSE сразу, без ожидания полного ответа. Это параметры передачи запросов, а не дополнительное правило на другой порт. Если NAS уже передаёт заголовки/поток, его правило перенаправления менять не нужно.

В настройках панели укажи public origin `https://llm.fnx.red` и доверенный IP NAS, чтобы HTTPS cookies и проверка Origin работали: [reverse proxy панели](reverse-proxy.md). Для `/v1/*` не нужны cookie/CSRF панели, авторизация API проверяется отдельно. В панели сохрани `https://llm.fnx.red/v1` в поле **OpenAI Base URL**. Это поле показывает адрес клиентам; DNS/TLS автоматически не создаются.

Дополнительный вход `http://192.168.1.77:11435/v1` можно включить через `-ApiPort 11435` или мастер. При этом `/v1` на порту панели продолжает работать. Для текущего правила NAS не используй `https://llm.fnx.red:11435/v1`: этот адрес обращается к другому порту NAS. При обновлении уже существующий дополнительный порт и ключ сохраняются.

## Поддерживаемые маршруты

- `GET /v1/models`
- `POST /v1/chat/completions`
- `POST /v1/completions`
- `POST /v1/embeddings`
- `POST /v1/responses`

Реальная поддержка каждого метода зависит от движка и модели. Tools/messages передаются без перевода. Для потоков дополнительно запрашивается include_usage, для PrismML — числовой прогресс. SSE пересылается порциями, без накопления полного ответа; долгий запрос не занимает цикл управления панели. Лимиты 0.7.0: одна выбранная модель, одна генерация одновременно (вторая получает 409), тело до 8 МиБ, запрос до 30 минут. Чтение списка моделей не занимает слот генерации; список содержит выбранную модель. Управляющие/native Ollama endpoints через этот порт не публикуются. CORS для произвольных веб-страниц не включён; интерфейс чата в панели отсутствует.

Если локальный движок уже защищён своим ключом, добавь `upstream_api_key` в его запись `config.json`. Этот ключ отправляется только локальному движку; клиентский ключ шлюза туда не передаётся. Request/response тела и API key шлюз в журналы не пишет.

Источники: [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility), [PrismML server](https://github.com/PrismML-Eng/llama.cpp/blob/prism/tools/server/README.md), [Nginx proxy module](https://nginx.org/en/docs/http/ngx_http_proxy_module.html).
