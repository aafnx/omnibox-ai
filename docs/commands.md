# Команды и ошибки

Повседневное управление доступно в [веб-панели](web-panel.md). CLI сохранён для SSH, диагностики и восстановления.

## Управление

`ai start [backend] [--context 128k]` использует `default_backend`, если имя не задано. Сначала проверяются права и наличие целевой службы; отсутствующая/отключённая целевая служба не приводит к остановке другого сервера. Далее останавливаются другие настроенные службы независимо от старого значения `exclusive`. При запуске закрепляются один слот PrismML и одна загруженная модель/параллельный запрос Ollama. После запуска проверяется готовность API: Bonsai `/health`, Ollama `/api/version`.

Повторный запуск работающего сервера не перезапускает его и не сбрасывает модель. При запуске Ollama проверяется сервер, а не наличие загруженной модели.

`ai stop` пытается остановить **все** настроенные службы. Даже если одна остановка не удалась, остальные будут обработаны; итоговый код — `1`, а не ложное сообщение об успехе. Отсутствующая служба пропускается. `ai stop prismml` (или `ai stop bonsai`) ограничивается указанной службой. `prismml` — имя движка в панели; его служба Windows называется `bonsai`, оба имени равноправны.

`ai restart` — последовательные stop/start выбранного сервера. После перезапуска применяется обычное правило эксклюзивного запуска.

Операции управления сериализованы системным именованным mutex. Параллельная команда ждёт до 10 секунд, затем возвращает ошибку. Никаких демонов или фоновых задач mutex не создаёт.

## Изменение контекста

| Команда | Когда применяется |
|---|---|
| `ai context` | Только показывает контекст backend по умолчанию |
| `ai context prismml` | Только показывает сохранённый контекст PrismML |
| `ai context prismml 128k` | Сохраняет в XML для следующего запуска; не останавливает модель |
| `ai start prismml --context 128k` | Сохраняет и запускает остановленный сервер |
| `ai restart prismml --context 128k` | Проверяет XML, останавливает сервер, сохраняет и запускает заново |
| `ai restart ollama --context 32k` | Меняет default Ollama и перезапускает службу |

Суффикс `k` означает 1024 токена; `m` — 1048576. Дробные значения запрещены. Программа принимает от 1024 до 1048576 токенов, но это **диапазон синтаксической проверки, не обещание поддержки моделью/видеокартой**. Для текущего Bonsai заявленный максимум модели — 262144; рабочий контекст 196608 ранее проверен только на коротком запросе.

Поддерживаются `--context 128k`, `--context=128k`, `-c 131072`. При уже работающем сервере `start` с контекстом возвращает ошибку без изменений: используй `restart`.

Для Prism меняется только `-c`/`--ctx-size` в `<arguments>`; для Ollama только env `OLLAMA_CONTEXT_LENGTH`. Перед записью проверяется `<id>` службы, сохраняется предыдущий XML, новый файл заменяет старый атомарно. Указанные флаги контекста нормализуются до одного `-c N`; другие аргументы и quoted paths сохраняются.

`ai context` показывает **настроенный**, не обязательно активный размер. У Ollama `num_ctx` в запросе/параметрах модели может переопределять серверный default. Проверяй фактическое значение через `ai status` для Bonsai / `ai ollama ps` для Ollama.

Настройки контекста сохраняются между остановками и загрузками Windows. `ai start` не применяет ожидающий контекст к уже работающему серверу: используй `ai restart`.

## Восстановление настроек

```powershell
ai restore prismml
```

Команда возвращает предыдущий XML. Если выбранная служба работала, она остановится и запустится с восстановленными настройками. Если была остановлена, загрузки модели не будет. Повторное восстановление уже восстановленных настроек ничего не меняет. Без истории команда сообщает об этом.

Если запуск или готовность API после изменения контекста не удались, `ai start/restart` сначала останавливает неудачный процесс, восстанавливает предыдущий XML и повторно запускает **только выбранный сервер, если он работал до команды**. Команда всё равно возвращает ошибку: выбранный новый контекст не применён. Другой backend, остановленный при переключении, автоматически не запускается.

Откат относится к запуску службы и готовности API. У Ollama модель загружается позже по запросу: последующий OOM или ошибка генерации этим механизмом не отслеживаются. У Bonsai проверка запуска также не гарантирует успешную генерацию на полностью заполненном контексте.

Рядом с XML программа хранит `.ai-previous` и `.ai-state.json`. Не нужно редактировать их вручную. Повторные изменения до успешного запуска сохраняют одну исходную точку отката. SHA256 обнаруживает внешние изменения XML/истории: программа отказывается перезаписывать их. Если остановка службы не удалась, XML при откате не перезаписывается. Старые backup-файлы предыдущих версий не удаляются.

## Диагностика без загрузки модели

`ai status` показывает:

| Поле | Значение |
|---|---|
| `Backend` | Имя в `config.json` |
| `Engine` | `prism` или `ollama` |
| `Service` | Состояние Windows-службы либо `Missing` |
| `Startup` | Тип запуска Windows-службы |
| `API` | `Ready`, `Unavailable` либо `-` для остановленной службы |
| `Context` | Контекст Bonsai из `/props` |
| `Sleeping` | Флаг сна Bonsai из `/props` |
| `model` | Отдельной строкой: файл Bonsai / загруженные модели Ollama |

У Ollama `Context` берётся из context_length единственной загруженной модели, если runtime отдаёт это поле. Sleeping для Ollama не определяется. Дополнительно выводится `nvidia-smi`, если утилита доступна. Отсутствие `nvidia-smi` не препятствует работе.

`ai status` — информационная команда: недоступный API отмечается в таблице, но сам по себе не даёт ненулевой exit code. Для автоматизации анализируй данные API отдельно; это не readiness-gate.

`ai logs [backend] [N] [stream]` читает текущие журналы встроенного runtime. `stream`: `all`, `err`, `out`, `host` (старый `wrapper` доступен для диагностики миграции). По умолчанию `N=60`; диапазон `1..10000`. Архивные ротации и непрерывное наблюдение (`tail -f`) в этой версии не реализованы.

## Сон и пробуждение ПК

```powershell
ai power
```

Повышенная сессия показывает `powercfg /lastwake`, `/waketimers`, `/requests` и `/devicequery wake_armed`. Первая команда сообщает источник последнего пробуждения, вторая — активные таймеры, третья — запросы приложений/драйверов, удерживающие систему от автоматического сна, четвёртая — разрешённые устройства. [Справка Microsoft](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options).

Наличие запущенного ИИ-сервера не устанавливает причину пробуждения. Для проверки сравни поведение после `ai stop`. Команда `ai power` не меняет настройки питания, таймеры, сетевую карту или WoL Home Assistant. `ai` не создаёт собственных таймеров пробуждения и не предотвращает сон Windows во время генерации.

## Передача в Ollama

`ai ollama ...` вызывает конкретный `executable` из конфигурации. Не использует поиск случайного `ollama.exe` в PATH и не меняет службы. stdout/stderr остаются стандартными; код возврата Ollama передаётся вызывающему процессу.

На время вызова `OLLAMA_HOST` устанавливается в `base_url` настроенного backend Ollama. Если XML доступен, `OLLAMA_MODELS` читается из `/service/env`, чтобы CLI использовал тот же каталог. После вызова переменные восстановлены. Значения хоста в окружении не могут незаметно перенаправить `ai ollama` на другой сервер.

Для сложных аргументов с метасимволами Windows CMD предпочтителен прямой вызов `.ps1`, избегая дополнительного разбора `.cmd`:

```powershell
& 'C:\tools\ai\ai.ps1' ollama run MODEL 'Текст с & и |'
```

Обычные вызовы `ai ollama list`, `ai pull MODEL`, `ai run MODEL "обычный текст с пробелами"` работают через `ai.cmd`. Оболочка не использует `Invoke-Expression`, не собирает аргументы в исполняемую строку и не перехватывает внутренние флаги Ollama вроде `--version`.

`ai ollama serve` передаётся как обычная команда: это **ручной foreground-запуск**, не управляемый службой `ai start ollama`. Не используй его одновременно с уже работающей службой на том же порту. `ai stop` управляет только зарегистрированными службами, не произвольными процессами.

## Частые ситуации

| Ситуация | Действие |
|---|---|
| `ai` не найден | Добавь `C:\tools\ai` в PATH текущей SSH-сессии; проверь полный путь `C:\tools\ai\ai.cmd` |
| Нужны повышенные права | Используй ту же повышенную SSH-сессию, где работал `Start-Service` |
| `служба завершилась` | `ai logs prismml 100 err`, затем host/out |
| API не готов за 180 с | `ai status`, `ai logs`; после смены контекста выполняется откат, без ожидающих настроек автоматического отката нет |
| В `ai status` два сервера Running | Выполни `ai stop`, затем `ai start prismml`; внешние команды обходят эксклюзивность |
| Ollama не соединяется | Явно `ai start ollama`; passthrough не запускает службу |
| Bonsai отвечает, но не хватает VRAM на длинном запросе | Посмотри err-журнал и память; оболочка не уменьшает контекст автоматически |
| Ошибка HTTP после запуска Bonsai | Проверь занятый порт; известный конфликт Steam WebHelper на 8080 решён портом 18080 |

Ошибки оболочки пишутся в stderr с префиксом `ai:` и кодом `1`. Справка/успешное управление — код `0`; native-вызов Ollama сохраняет свой код. Проверка в PowerShell:

```powershell
$LASTEXITCODE
```

## Адреса и восстановление входа

```powershell
ai access
```

Показывает LAN/HTTPS-адрес панели, OpenAI Base URL, доверенный IP NAS, включение API key. Пароль/hash/ключ не печатаются. `ai panel info` — эквивалентная команда. Она работает даже при отсутствии конфигурации движков, если есть `panel.json`.

```powershell
ai password reset
```

В повышенной сессии введи новый пароль скрыто; Enter генерирует пароль. Для генерации без вопроса:

```powershell
ai password reset --generate
```

Сгенерированный пароль показывается один раз. Изменяется только hash в panel.json; сети/NAS/API и параметры моделей сохраняются. Работающая панель перезапускается и сбрасывает сессии входа, ИИ-движки не перезапускаются. Эквивалент: `ai panel reset-password [--generate]`.

`ai ollama serve` запрещён: используй `ai start ollama`. `ai run <model>` требует запущенной Ollama, выключает другой управляемый движок, выгружает предыдущую Ollama-модель и сохраняет выбранное имя. Native CLI-запросы не проходят через журнал OpenAI-шлюза.

## Обновление программы

`ai update` скачивает встроенный установщик из `aafnx/omnibox-ai` (main) через установленный GitHub CLI и обновляет текущую установку без повторных вопросов. Контекст, NAS, пароль и ключ API сохраняются; ИИ-движки не запускаются. Для повторного мастера предусмотрен параметр установщика `-Reconfigure`. Нужны права администратора и вход `gh auth login --hostname github.com --git-protocol https --web` под тем же Windows-пользователем. Git и клонирование репозитория не требуются. `ai update --token` использует прежний скрытый ввод токена; без gh этот способ выбирается автоматически. Ошибка доступа/скачивания не запускает установщик и не останавливает службы. Установщик может подключить существующую авторизацию gh к обновлениям панели через защищённое Windows DPAPI-хранилище; разовый токен CLI не сохраняется. [Подробная установка](install.md).

### Выбор версии

| Команда | Действие |
|---|---|
| `ai update` | Последняя версия из `main` |
| `ai update --list` | Доступные версии из `releases.json` с примечаниями; отмечены последняя и установленная. Права администратора не нужны |
| `ai update 0.9.5` | Указанная версия: обновление, переустановка той же или откат на более старую |
| `ai update 0.9.5 --token` | То же с ручным вводом токена; токен запрашивается один раз |

Установщик нужной версии скачивается по коммиту её выпуска. До запуска проверяется, что внутри него именно запрошенная версия. Перед запуском команда сообщает, что произойдёт: установка, обновление, переустановка или откат. Пока работает установщик, команда держит замок установки: веб-обновление и второй `ai update` в это время получают отказ.

При откате настройки сохраняются, но функции более новых версий становятся недоступны. В версиях до 0.9.5 нет транзакционной установки: при сбое такого установщика автоматического отката не будет, только резервная копия в `backups`. Поверх текущей системы можно ставить версии начиная с 0.9.4: более старые установщики несовместимы со службами на `Service.Host.exe` и в список не входят.
