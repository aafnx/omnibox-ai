# Команды и ошибки

## Управление

`ai start [backend]` использует `default_backend`, если имя не задано. Сначала проверяются права и наличие целевой службы; отсутствующая/отключённая целевая служба не приводит к остановке другого сервера. Далее, при `exclusive: true`, останавливаются другие настроенные службы. После запуска проверяется готовность API: Bonsai `/health`, Ollama `/api/version`.

Повторный запуск работающего сервера не перезапускает его и не сбрасывает модель. При запуске Ollama проверяется сервер, а не наличие загруженной модели.

`ai stop` пытается остановить **все** настроенные службы. Даже если одна остановка не удалась, остальные будут обработаны; итоговый код — `1`, а не ложное сообщение об успехе. Отсутствующая служба пропускается. `ai stop bonsai` ограничивается указанной службой.

`ai restart` — последовательные stop/start выбранного сервера. После перезапуска применяется обычное правило эксклюзивного запуска.

Операции управления сериализованы системным именованным mutex. Параллельная команда ждёт до 10 секунд, затем возвращает ошибку. Никаких демонов или фоновых задач mutex не создаёт.

## Диагностика без загрузки модели

`ai status` показывает:

| Поле | Значение |
|---|---|
| `Backend` | Имя в `config.json` |
| `Engine` | `prism` или `ollama` |
| `Service` | Состояние Windows-службы либо `Missing` |
| `Startup` | Тип запуска Windows-службы |
| `API` | `Ready`, `Unavailable` либо `-` для остановленной службы |
| `Context` | Контекст Bonsai из `/props` |
| `Sleeping` | Флаг сна Bonsai из `/props` |
| `model` | Отдельной строкой: файл Bonsai / загруженные модели Ollama |

У Ollama `Context`/`Sleeping` пустые: эта первая версия не объединяет индивидуальные контексты и сроки выгрузки всех моделей в одно поле. Дополнительно выводится `nvidia-smi`, если утилита доступна. Отсутствие `nvidia-smi` не препятствует работе.

`ai status` — информационная команда: недоступный API отмечается в таблице, но сам по себе не даёт ненулевой exit code. Для автоматизации анализируй данные API отдельно; это не readiness-gate.

`ai logs [backend] [N] [stream]` читает текущие журналы WinSW. `stream`: `all`, `err`, `out`, `wrapper`. По умолчанию `N=60`; диапазон `1..10000`. Архивные ротации и непрерывное наблюдение (`tail -f`) в этой версии не реализованы.

## Передача в Ollama

`ai ollama ...` вызывает конкретный `executable` из конфигурации. Не использует поиск случайного `ollama.exe` в PATH и не меняет службы. stdout/stderr остаются стандартными; код возврата Ollama передаётся вызывающему процессу.

На время вызова `OLLAMA_HOST` устанавливается в `base_url` настроенного backend Ollama. Если XML доступен, `OLLAMA_MODELS` читается из `/service/env`, чтобы CLI использовал тот же каталог. После вызова переменные восстановлены. Значения хоста в окружении не могут незаметно перенаправить `ai ollama` на другой сервер.

Для сложных аргументов с метасимволами Windows CMD предпочтителен прямой вызов `.ps1`, избегая дополнительного разбора `.cmd`:

```powershell
& 'C:\tools\ai\ai.ps1' ollama run MODEL 'Текст с & и |'
```

Обычные вызовы `ai ollama list`, `ai pull MODEL`, `ai run MODEL "обычный текст с пробелами"` работают через `ai.cmd`. Оболочка не использует `Invoke-Expression`, не собирает аргументы в исполняемую строку и не перехватывает внутренние флаги Ollama вроде `--version`.

`ai ollama serve` передаётся как обычная команда: это **ручной foreground-запуск**, не управляемый службой `ai start ollama`. Не используй его одновременно с уже работающей службой на том же порту. `ai stop` управляет только зарегистрированными службами, не произвольными процессами.

## Частые ситуации

| Ситуация | Действие |
|---|---|
| `ai` не найден | Добавь `C:\tools\ai` в PATH текущей SSH-сессии; проверь полный путь `C:\tools\ai\ai.cmd` |
| Нужны повышенные права | Используй ту же повышенную SSH-сессию, где работал `Start-Service` |
| `служба завершилась` | `ai logs bonsai 100 err`, затем wrapper/out |
| API не готов за 180 с | `ai status`, `ai logs`; служба не останавливается автоматически по таймауту |
| В `ai status` два сервера Running | Выполни `ai stop`, затем `ai start bonsai`; внешние команды обходят эксклюзивность |
| Ollama не соединяется | Явно `ai start ollama`; passthrough не запускает службу |
| Bonsai отвечает, но не хватает VRAM на длинном запросе | Посмотри err-журнал и память; оболочка не уменьшает контекст автоматически |
| Ошибка HTTP после запуска Bonsai | Проверь занятый порт; известный конфликт Steam WebHelper на 8080 решён портом 18080 |

Ошибки оболочки пишутся в stderr с префиксом `ai:` и кодом `1`. Справка/успешное управление — код `0`; native-вызов Ollama сохраняет свой код. Проверка в PowerShell:

```powershell
$LASTEXITCODE
```
