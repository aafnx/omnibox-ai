# Автоматизации

Раздел «Автоматизации» (на телефоне — «Авто») хранит ваши собственные задачи для моделей: разовые и по расписанию, с поиском в интернете или конфиденциальные — только на ПК. Любую автоматизацию можно создать с нуля или из заготовки и потом изменить: «Настроить» в её карточке.

Автоматизация состоит из **шагов** — сколько угодно, до 20. Шаги выполняются по порядку. «Новая автоматизация» начинает с одного шага одного из трёх видов, а в настройках добавляются следующие:

| Вид | Что делает | Результат |
|---|---|---|
| **Задача** | что угодно своими словами: «Найди новости о {{тема}} за неделю», «Переведи на английский», «Сравни два договора» | ответ модели: копировать или скачать `.md` |
| **Поля из данных** | берёт из текста, фото или файлов заданные вами поля и проверяет их | значения: текстом, CSV, JSON или сразу в документ |
| **Документ по шаблону Word** | заполняет ваш шаблон `.docx`, не меняя оформления | документ Word, а также текст, CSV или JSON |

## Шаги

- «Шаг: задача» и «Шаг: поля из данных» добавляют шаг в конец; стрелки меняют порядок, крестик убирает шаг. Шаг можно назвать — «Поиск», «Перевод», — иначе он «Шаг 1», «Шаг 2».
- **Каждый шаг видит данные запуска и результаты всех предыдущих шагов**: ответ задачи — текстом, поля — строками «Поле: значение». Поэтому второй шаг пишется просто: «Переведи на английский», «Сделай из найденного сводку», «Напиши письмо с этими данными».
- **У каждого шага своя модель и свой поиск.** Модель шага по умолчанию — модель автоматизации; можно, например, искать облачной моделью, а писать итог локальной. Поиск в интернете и чтение страниц включаются для каждого шага отдельно.
- **Документ по шаблону — всегда последний шаг**: его значения вы проверяете перед сборкой файла. Шаги перед ним готовят данные — например, «Поля из данных» распознают паспорт, а документ вписывает их в договор. Автоматизация документа начинается из шаблона Word; шаги перед документом добавляются в её настройках.
- **Указания для модели** и **«Конфиденциально»** действуют на все шаги.
- Шаг, который не удался, останавливает запуск: показываются результаты выполненных шагов и ошибка с названием шага.
- Результат запуска — последний шаг. Выполненные шаги перед ним видны свёрнутыми над результатом и в истории.

Пример — «Сводка новостей» из заготовки: шаг «Поиск» ищет новости о `{{тема}}` на русском и английском, шаг «Сводка» делает из найденного сводку на русском со ссылками.

### Сайты шага

У шага есть поле **«Сайты»** — например, `sozd.duma.gov.ru`. Если оно заполнено:

- шаг **ищет только на этих сайтах** (поиск с оператором `site:`);
- открывает найденные страницы сайтов и **переходит по ссылкам между ними** — например, из списка законопроектов в карточку законопроекта; модель видит под каждой прочитанной страницей список её ссылок на эти сайты;
- читает до 15 страниц за шаг (без сайтов — до 5). Страницы других сайтов шаг не открывает, даже если на них ведут ссылки.

Поиск и чтение страниц у такого шага включены всегда. Переходить по ссылкам умеет модель, которая вызывает инструменты (в списке моделей — значок инструментов); остальные модели читают только найденные поиском страницы. Сайт должен открываться с ПК: если сайт пускает только из России, ПК должен быть там же. Страницы, которые собираются скриптами в браузере, не читаются — их текста нет в ответе сайта.

Заготовки — **«Паспорт РФ»** (поля паспорта с фото, конфиденциально, с проверкой серии, номера, дат и кода подразделения) **«Сводка новостей»** (два шага: поиск и сводка, с историей) и **«Законопроекты Госдумы»** — поиск на `sozd.duma.gov.ru` законопроектов по теме `{{тема}}`: номер, название, кто внёс, стадия, последнее событие, ссылка на карточку, затем сводка — что изменилось за месяц. Её удобно поставить на расписание, например по будням в 9:00: новые результаты отмечаются в карточке. Это обычные автоматизации: в них можно поменять всё.

## Задача

- **Задача** — что сделать, своими словами. Слово в двойных фигурных скобках — `{{тема}}`, `{{период}}` — спрашивается при каждом запуске, так одна автоматизация служит для разных тем.
- **Указания для модели** — как оформить ответ: «списком», «с ссылками на источники», «не длиннее страницы».
- При запуске можно добавить данные: текст, фото, файлы Word, Excel, CSV или текстовые — например, документ для перевода или две таблицы для сравнения.
- Ответ показывается с источниками, если модель искала в интернете. Его можно скопировать или скачать файлом `.md`.

## Поля из данных

Вы задаёте список полей: название, подсказку («в виде 123-456», «полностью») и **тип** — по нему значение проверяется:

| Тип | Что проверяется |
|---|---|
| Текст | ничего — любое значение |
| Только цифры | нет букв и знаков |
| Число, сумма | число, можно с пробелами и дробной частью: «1 250 000,50» |
| Дата / Дата не в будущем | ДД.ММ.ГГГГ, ГГГГ-ММ-ДД или «12» октября 2026 г.; вторая — что дата уже наступила |
| Телефон / Email | 10–15 цифр; адрес вида имя@домен |
| Серия паспорта / Номер паспорта | 4 и 6 цифр |
| Код подразделения | в виде 123-456 |
| ИНН / СНИЛС / ОГРН / ОГРНИП | число цифр и контрольная цифра |
| КПП / БИК / Расчётный счёт | 9 знаков; 9 цифр, начиная с 0; 20 цифр |

Проверку выполняет OmniBox после ответа модели, а не сама модель: поле, которое её не прошло, выделено и подписано («Серия паспорта — 4 цифры»). Поправьте значение и выберите, в каком виде его получить: текстом, таблицей CSV, JSON — или **«В документ: …»**: значения переходят в автоматизацию документа по одинаковым названиям полей («Фамилия» → «Фамилия»), и остаётся проверить их и нажать «Документ Word».

## Документ по шаблону Word

**Создание — один раз.**

1. «Новая автоматизация» → «Документ по шаблону Word» → выберите `.docx`: договор с пустыми местами «____», ««__» ________ 20__ г.» или с данными образца («Иванов Иван Иванович»). Файл `.doc` сначала сохраните в Word как `.docx`.
2. Назовите автоматизацию, выберите режим и модель, при желании напишите указания для модели («даты — «12» октября 2026 г.», «суммы цифрами и прописью»), нажмите «Сохранить».
3. OmniBox сохраняет шаблон, а модель сама читает его и предлагает поля с их типами: «ФИО покупателя» — текст, «Дата договора» — дата, «Цена» — число, «ИНН продавца» — ИНН. У каждого поля видно его места в документе, само место выделено. Метки вида `{{ФИО}}` становятся полями сразу, без модели.
4. Поправьте, что нужно: **название**, **подсказку** («полностью, в родительном падеже»), **тип** — значение потом проверяется по нему, как в «Полях из данных». Лишнее уберите крестиком. Сохраните.
5. Чего-то не хватает — **«Добавить поле»**: название, тип и текст, который поле заменит, — так, как он стоит в шаблоне («____», «Иванов И. И.», «15 000»). OmniBox найдёт этот текст во всём шаблоне, и каждое место станет местом поля; если поле с таким названием уже есть, места добавятся к нему. Можно и ещё раз нажать «Найти поля моделью».

**Запуск.**

1. «Запустить» → дайте данные: текст, фото (паспорт, свидетельство, скан), файлы Word, Excel, CSV или текстовые. Можно вместе.
2. «Распознать»: модель подбирает значение каждого поля и пишет, откуда оно взято. Поля без данных выделены — впишите значение или оставьте место пустым (в документе останется «____»).
3. Проверьте и поправьте значения, затем выберите, в каком виде их получить:
   - **Документ Word** — шаблон с вписанными значениями;
   - **Текстом** — «Поле: значение», копируется в буфер обмена;
   - **Таблица CSV** — для Excel (разделитель «;»);
   - **JSON** — для других программ.

Текст, CSV, JSON и `.md` собираются прямо в браузере: на ПК ничего не отправляется.

### Как сохраняется оформление

Модель не видит и не пишет файл Word: она отвечает только «поле → значение». Вписывает значения сам OmniBox — меняет текст в найденных местах, и вписанный текст получает оформление того места: шрифт, жирность, подчёркивание. Всё остальное в файле — стили, таблицы, колонтитулы, нумерация, картинки — остаётся байт в байт. Табуляции и разрывы строк вокруг места сохраняются. Перенос строки в значении становится переносом строки в Word.

Если шаблон заменить другим файлом, поля нужно найти заново: места, которых больше нет в документе, OmniBox не заполняет и сообщает об этом.

## Что разрешено автоматизации

Это решается в настройках каждой автоматизации, и карточка в списке всегда показывает, что ей разрешено.

| | Конфиденциально | Обычная |
|---|---|---|
| Модель | только на этом ПК | на ПК, OpenRouter или ChatGPT |
| Поиск в интернете и чтение найденных страниц | нет | по выбору для каждого шага |
| История запусков | нет | по выбору |
| Расписание | нет | по выбору (для задач) |
| Текст запроса в журнале содержимого `/v1` | никогда | никогда |
| Фото и файлы запуска на диске | нет | нет |

- **Конфиденциально** — для персональных данных: служба отклоняет облачную модель — у автоматизации и у любого шага — и при сохранении, и при запуске, даже если в чате выбрана облачная, и выключает поиск, историю и расписание, что бы ни пришло в запросе. В интернет не уходит ничего: ни данные, ни поисковые запросы.
- **Поиск в интернете** работает так же, как в чате: поисковая система из настроек, модель сама составляет запросы, «Читать найденные страницы» открывает лучшие страницы целиком. В поиск уходят только поисковые запросы модели. У шага с **сайтами** поиск идёт только по ним, а читаются только их страницы.
- Других инструментов у автоматизаций нет: ни вызова программ, ни доступа к файлам ПК.
- Запросы к локальной модели идут через ту же очередь `/v1`, что и чат (одна модель, одна генерация), но через отдельный вход: их текст не пишется в журнал содержимого даже при `storage.request_log: content`. В списке запросов на странице «Сервер» видно только, что запрос был, — с временем и токенами.
- Модель не запускается сама: если локальная модель автоматизации или шага не запущена, окно запуска говорит об этом и предлагает кнопку «Запустить модель» — это ваше действие, как выбор модели в чате. Запустить её можно и в списке моделей над чатом. Если шаги используют разные модели на ПК, окно предупредит: одновременно работает одна. Для фото нужна модель со зрением — у неё в списке пометка «видит фото».

## Запуск и ход выполнения

«Запустить» начинает запуск в службе, и окно следит за ним: под кнопкой виден **ход выполнения** — по строке на событие, со временем от начала шага:

- какие поисковые запросы ушли и сколько найдено;
- какие страницы прочитаны, какие не открылись и почему (сайт не ответил, ответил ошибкой, страница собирается скриптами и текста в ней нет);
- когда модель получила запрос (и какой он длины) и за сколько ответила.

Окно можно закрыть — запуск продолжится, а результат попадёт в историю, если она включена. «Остановить» прерывает запуск. Ход выполнения сохраняется в истории вместе с результатом: по нему видно, где ушло время, если шаг не уложился.

На шаг отводится 10 минут, шагу с сайтами — 20. Если модель не уложилась, ход выполнения подскажет почему; помогает облачная модель (она быстрее отвечает на длинные запросы со страницами), выключенные размышления у локальной модели или задача поуже.

## История запусков

Включается в настройках обычной автоматизации — «Хранить историю запусков»; у конфиденциальной её нет. Вкладка «История» в окне запуска показывает результаты: время, вручную или по расписанию, данные запуска текстом, ответ или значения полей, ошибку, если запуск не удался. Новые результаты расписания отмечены в карточке («новых: 2»), пока историю не откроют.

- Хранится текст: данные запуска (без фото и файлов — только их имена), ответ, значения, источники.
- Срок хранения — тот же, что у чатов (Настройки → Хранение), и не больше 200 запусков на автоматизацию.
- «Удалить историю» и удаление автоматизации стирают её сразу, без корзины.

Без истории результат живёт только в открытом окне: закрытие окна стирает данные и значения на странице. Готовый документ Word хранится в памяти службы час, чтобы его можно было скачать ещё раз, и на диск не записывается.

## По расписанию

Автоматизацию, которая начинается с задачи и не собирает документ, можно запускать саму: каждый день в заданное время, по выбранным дням недели или каждые несколько часов, начиная с заданного времени. Нужны история (туда попадает результат), модель у автоматизации или у каждого шага и значения всех слов `{{…}}` всех шагов — они задаются рядом с расписанием.

- Служба держит один таймер — до ближайшего запуска — и переставляет его только при изменении автоматизаций и после запуска. Пока ни у одной автоматизации нет включённого расписания, таймера нет совсем.
- Используются часы и часовой пояс ПК. ПК должен быть включён, а служба запущена; запуск, пропущенный, пока ПК спал или был выключен, потом не повторяется.
- Расписание не запускает модели: если локальная модель не запущена, в истории будет ошибка «модель не запущена». Для расписания удобнее облачная модель или модель, которая работает постоянно.
- Карточка показывает расписание и время следующего запуска.

На ПК автоматизации, шаблоны и история хранятся в `automations/` в каталоге данных, с правами только службы. Удаление автоматизации сразу стирает её шаблон и историю, без корзины; `ai uninstall` удаляет всё.

## Что дальше

- Повторяющиеся строки таблиц (список товаров), PDF на входе, несколько документов за раз, шаблоны Excel.
- Другие инструменты для задач: например, отправка результата в Telegram или на почту — только по явному выбору в автоматизации.
