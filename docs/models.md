# Модели: настройки и скорость

## Установленные модели

Раздел «Модели и настройки» → **Установленные модели** показывает все модели выбранного движка на диске: параметры (27B), квантизацию, размер, обученный контекст и возможности значками-иконками, как на openrouter.ai (при наведении — подсказка):

| Значок | Что значит | Откуда известно |
|---|---|---|
| Рассуждения | модель умеет думать перед ответом (thinking) | шаблон чата в GGUF (`<think>`, `enable_thinking`, каналы gpt-oss); у Ollama — её `capabilities` |
| Инструменты | вызов инструментов (function calling) | шаблон чата; у Ollama — `capabilities` |
| Зрение | работа с изображениями | рядом лежит проектор `mmproj` этой модели; у Ollama — `capabilities` |
| MoE | Mixture of Experts: на токен работает часть весов | число экспертов в GGUF |

У каждой модели — ссылка на её страницу на Hugging Face (для моделей, скачанных через панель; для более старых — поиск по имени) или в библиотеке Ollama, кнопка **Выбрать** (подставляет модель в форму настроек — сохраните или примените) и **Удалить**. Модель, выбранную в настройках или нужную для отката, удалить нельзя: сначала выберите и сохраните другую. Список Ollama доступен, пока Ollama запущена.

## Зрение: изображения в запросах

Модель видит изображения, только если llama-server запущен с её **проектором** — отдельным файлом `mmproj-….gguf` из того же репозитория. Без него клиент получает ошибку `image input is not supported … you may need to provide the mmproj`.

1. Модель из «Добавить модель» скачивается вместе со своим проектором (обычно `F16`), если он есть в репозитории. Для уже установленной модели нажмите **Скачать проектор** под полем «Зрение»: панель найдёт проектор в репозитории модели, скачает его и выберет в настройках. Если источник модели неизвестен (скачана не через панель), откроется поиск по её имени.
2. В настройках модели поле **Зрение (изображения)** по умолчанию «Авто»: при запуске панель находит проектор этой модели рядом с ней и передаёт `--mmproj`. Подсказка под полем говорит, найден ли проектор. Можно выбрать проектор вручную или выключить зрение.
3. Примените настройки. В «Установленных моделях» у модели появится значок «Зрение».

Проектор занимает VRAM (0,5–1,5 ГБ); пресет «Базовый» и оценка размещения его учитывают. Зрение есть не у всех моделей: если в репозитории нет `mmproj`, модель изображения не принимает — для картинок возьмите, например, Gemma 3 (значок «Зрение» в результатах поиска). У Bonsai 2 проектор нужно искать в репозитории PrismML; если его там нет, изображения этой модели недоступны.

Запрос с изображениями к `/v1` может весить до 32 МБ (картинки передаются в base64). В журнал содержимого запросов картинки не записываются — вместо них остаётся пометка с размером. Если через NAS запросы с картинками обрываются, увеличьте в обратном прокси NAS допустимый размер тела запроса.

## Добавить модель

Один раздел вместо прежних «Каталога» и «Скачать новую модель»:

- **Популярные** — кнопки с проверенными репозиториями GGUF (Bonsai 2, Ornith, Gemma 3, Qwen3, gpt-oss, Mistral Small, DeepSeek R1): сразу открывают список файлов для скачивания;
- В списке файлов репозитория — возможности модели и у каждого файла пометка, запустится ли он на этом ПК: целиком в VRAM, с коротким контекстом, MoE с экспертами в RAM, частью слоёв в RAM (медленно) или не поместится. Это прикидка по размеру файла; точные настройки подберёт «Базовый» после скачивания.
- **Поиск на Hugging Face** — по названию; если фильтр GGUF ничего не вернул, панель повторяет поиск шире и оставляет репозитории с GGUF;
- **По прямой ссылке или имени Ollama** — раскрывающийся блок для ссылки `…/resolve/…/model.gguf` или имени `модель:тег`.

Скачанная модель появляется в «Установленных моделях»; в память она не загружается.

## Пресет «Базовый»

«Базовый» — рекомендуемые настройки для этого ПК (RTX 5080, 16 ГБ VRAM). Он встроен, его нельзя удалить, и он первый в списке пресетов в разделе «Модели и настройки». Новый движок PrismML сразу получает его значения.

При применении пресет подбирается под выбранную модель и видеокарту:

- Flash Attention включён, KV-кеш `q8_0` (вдвое меньше `f16` почти без потери качества), batch 2048 и ubatch 512 — быстрее читает длинные запросы;
- контекст — самый длинный из 128k, 64k, 32k, 16k, 8k, при котором веса и KV-кеш целиком помещаются в VRAM с запасом 0,75 ГБ для Windows и браузера; не длиннее обученного контекста модели;
- если модель больше VRAM: у MoE-моделей эксперты части слоёв уходят в RAM («Слои MoE в RAM»), у обычных — часть слоёв на GPU («RAM + VRAM»);
- модель, имя в API, Thinking и сэмплинг пресет не меняет.

Расчёт идёт по заголовку GGUF (слои, головы KV, обученный контекст) и объёму VRAM из `nvidia-smi`; у гибридных моделей (Qwen3.5/3.6) KV-кеш учитывается только для слоёв полного внимания. Работающий сервер перезапускается с новыми настройками; если запуск не удался, настройки откатываются.

## Почему модель вдруг медленная

Если веса и KV-кеш не помещаются в VRAM, а размещение — «VRAM · GPU», Windows не сообщает об ошибке: видеодрайвер NVIDIA выносит часть памяти в RAM, и генерация замедляется в 5–10 раз. Типичная причина — большой контекст с кешем `f16`: для 27B-модели контекст 192k с `f16` занимает больше 16 ГБ.

Панель проверяет это сама: при открытии «Модели и настройки» и при смене модели, контекста, типа кеша или размещения. Если настройки не помещаются, над кнопками появится предупреждение с кнопкой **Применить «Базовый»**. Проверка читает только заголовок GGUF и запускается по действию, без фонового опроса.

Чтобы переполнение не замедляло работу молча, а сразу приводило к понятной ошибке запуска (и панель откатывала настройки), в панели управления NVIDIA можно выключить перенос памяти: **Управление параметрами 3D → Программные настройки → `llama-server.exe` → CUDA — политика отката системной памяти → Предпочитать отсутствие отката**.

## Как сравнить

После смены настроек нажмите **Тест модели**: он показывает время до первого токена и скорость генерации в ток/с. «Оценить размещение в VRAM/RAM» показывает, сколько займут веса и KV-кеш с текущими настройками.
