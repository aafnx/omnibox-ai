# Установка и обновление

OmniBox AI — один файл `omnibox` (`omnibox.exe` на Windows). Его ставит и обновляет одна и та же команда.

## Установка на Windows

1. Откройте PowerShell **от имени администратора** (подойдёт встроенный Windows PowerShell).
2. Выполните:

   ```powershell
   gh release download --repo aafnx/omnibox-ai --pattern install.ps1 --dir $env:TEMP --clobber
   powershell -NoProfile -ExecutionPolicy Bypass -File $env:TEMP\install.ps1
   ```

   Если `gh` не установлен, скачайте `install.ps1` со страницы выпуска в браузере и запустите вторую строку. Скрипт попросит GitHub token с правом чтения репозитория (Contents: Read); токен вводится скрытно и нигде не сохраняется.
3. Ответьте на вопросы. **Enter принимает ответ в скобках**:

   | Вопрос | По умолчанию |
   |---|---|
   | Порт панели и API | 8800 |
   | Адреса панели | IPv4 этого ПК, имя компьютера, `localhost` |
   | HTTPS-адрес через NAS | `https://llm.fnx.red` (`-` — без NAS) |
   | IP NAS | `192.168.1.10` |
   | Адрес API для клиентов | `https://llm.fnx.red/v1`; без NAS — `http://<IPv4>:8800/v1` |
   | Установить PrismML и Ollama | да, последние версии |
   | Каталог моделей | `C:\ProgramData\OmniBox AI\models` |

4. Сразу после установки, до скачивания движков, установщик покажет **пароль панели** и **API key**. Они показываются один раз и нигде не хранятся в открытом виде — сохраните их в менеджере паролей. Пароль можно сменить в панели (вкладка «Подключение»); если он потерян — `ai password reset`, новый API key — `ai key new` (от имени администратора). Повторный запуск установщика — это обновление: пароль и ключ не меняются и не показываются.

Неинтерактивная установка со всеми ответами по умолчанию: добавьте `-Yes` (`install.ps1 -Yes`). Определённая версия: `-Version 0.18.0`. Адрес NAS, его IP и адрес API для клиентов потом меняются в панели: «Подключение» → настройки API.

Скрипт проверяет SHA256 выпуска до запуска. Если на любом шаге установки происходит ошибка, всё сделанное отменяется. Если установку прервали (выключили ПК, закрыли окно), повторный запуск той же команды сначала вернёт прежнее состояние: журнал шагов хранится в каталоге программы до конца установки.

## Удаление PowerShell-версии (0.17.1 и раньше)

Установщик прежнюю версию не трогает: она продолжает работать рядом (панель на 18090), пока вы её не удалите. После того как новая панель открылась и работает, выполните один раз в PowerShell от имени администратора:

```powershell
gh release download v0.18.0 --repo aafnx/omnibox-ai --pattern remove-old-version.ps1 --dir $env:TEMP --clobber
powershell -NoProfile -ExecutionPolicy Bypass -File $env:TEMP\remove-old-version.ps1
```

Скрипт показывает, что найдено, и спрашивает подтверждение (`-Yes` — без вопроса). Затем:

1. останавливает и удаляет службы прежней версии (`omnibox-ai`, `bonsai`, `ollama` — по её `config.json`);
2. **переносит модели** в каталоги моделей новой версии: GGUF — в каталог PrismML, модели Ollama (`blobs`, `manifests`) — в каталог Ollama. Каталоги берутся из `C:\ProgramData\OmniBox AI\config.json`. Файл, который уже есть в новом каталоге, не перезаписывается;
3. удаляет правила Firewall `omnibox-ai-panel` и `omnibox-ai-api`, запись в пользовательском PATH и строку PATH в профиле PowerShell;
4. удаляет каталог прежней версии (обычно `C:\tools\ai`), каталоги движков, созданные для неё (с XML-профилем службы рядом с исполняемым файлом), и её журналы.

Каталог, в котором остались непереносимые модели, не удаляется — скрипт об этом сообщит. Нестандартный каталог прежней версии: `-Root D:\ai`. После этого перенастройте NAS: upstream `http://192.168.1.77:8800` вместо `:18090`.

Скрипт не входит в программу: он нужен один раз при переходе на Go-версию.

## Установка на Linux

```sh
gh release download --repo aafnx/omnibox-ai --pattern install.sh --dir /tmp --clobber && sudo sh /tmp/install.sh
```

Параметры: `--yes`, `--version 0.18.0`. Откройте в межсетевом экране TCP-порт панели (8800) для локальной сети.

## Обновление

```sh
ai update            # последняя версия
ai update 0.19.0     # определённая версия, в том числе откат на более старую
```

Команда запускается от имени администратора (Windows) или через `sudo` (Linux). Она берёт GitHub token из `GH_TOKEN`/`GITHUB_TOKEN`, из входа в `gh`, из токена, сохранённого в панели, или спрашивает его скрыто; введённый в терминале token не сохраняется и передаётся только GitHub API, а сам файл скачивается по подписанной ссылке без него. `ai update --check` только сообщает, есть ли новая версия, и показывает её изменения. Выпуск сверяется с `SHA256SUMS`, затем запускается его установщик.

Из панели: вкладка «Обновления» → «Проверить обновления» → «Обновить до x.y.z». Служба панели работает от имени системы и не видит ваш вход в `gh`, поэтому панели нужен свой GitHub token — один раз:

1. В блоке «GitHub token для обновлений» нажмите **Создать токен на GitHub** — откроется форма с готовыми настройками: название, только чтение содержимого (Contents: Read), владелец `aafnx`, срок 1 год.
2. В «Repository access» выберите **Only select repositories → omnibox-ai** (репозиторий ссылка заранее не выбирает) и нажмите «Generate token».
3. Вставьте токен в панели и нажмите «Проверить и сохранить»: панель проверит его на GitHub и сохранит зашифрованным (DPAPI) в `run/github-token.bin`. Токен в панель больше не возвращается; срок его действия показан рядом. «Удалить токен» стирает его с ПК, `ai uninstall` — тоже.

Другую версию или откат — «Другая версия или откат». Выпуск скачивается и проверяется так же, установка идёт во временной службе `omnibox-update`; панель перезапустится примерно через минуту и покажет результат (подробности — `logs/update.log`). Token через интернет вводите только на HTTPS-адресе NAS.

Если команда `ai` не работает, обновляет та же команда, что и установка. Настройки, пароль, API key, вход в панель, модели и журналы сохраняются; службы переключаются на новую версию, панель перезапускается. Если новая панель не отвечает, установщик возвращает прежнюю версию. Работающий движок переходит на новую версию при следующем запуске.

## Запуск, остановка и автозапуск

От имени администратора (Linux — через `sudo`):

```sh
ai off                     # выключить всё: движки, панель и API
ai on                      # включить панель и API (и модель, выбранную «при старте»)
ai on prismml              # включить и сразу запустить PrismML с выбранной моделью
ai autostart off           # не запускать OmniBox вместе с Windows
ai autostart on            # запускать (так настроено после установки)
ai autostart model prismml # при загрузке ПК запускать и модель; off — не запускать
```

То же в панели: «Подключение» → «Запуск и выключение». Модель при старте запускается один раз за загрузку ПК: перезапуск службы, обновление или сбой остановленную модель не запускают. После «Выключить OmniBox полностью» панель недоступна, пока не выполнена `ai on` или ПК не перезагружен с включённым автозапуском.

## Где что лежит

| | Windows | Linux |
|---|---|---|
| Программа | `C:\Program Files\OmniBox AI\bin\<версия>\omnibox.exe` (текущая и предыдущая) | `/opt/omnibox/bin/<версия>/omnibox` |
| Команда `ai` | `C:\Program Files\OmniBox AI\ai.cmd` (в PATH) | `/usr/local/bin/ai` |
| Данные | `C:\ProgramData\OmniBox AI` — `config.json`, `logs\`, `engines\`, `models\`, `run\` | `/var/lib/omnibox` |
| Службы | `omnibox` (панель, автозапуск), `omnibox-prismml`, `omnibox-ollama` (движки, запуск из панели) | те же unit-файлы systemd |

Каталог данных доступен только SYSTEM и администраторам (Linux — root): там настройки, журналы и, если вы включили запись, содержимое запросов.

## Удаление

От имени администратора (Linux — через `sudo`):

```sh
ai uninstall
```

Команда показывает, что будет удалено, задаёт один вопрос и удаляет OmniBox AI полностью, без следов в системе:

- службы `omnibox`, `omnibox-prismml`, `omnibox-ollama` и временную службу обновления `omnibox-update`, если она осталась;
- правило Firewall, команду `ai` и её запись в PATH;
- каталог программы (на Windows — через несколько секунд после выхода: работающую программу Windows не удаляет);
- данные: настройки, пароль, API key, журналы, скачанные движки и модели;
- временные файлы прерванного `ai update`.

Если каталог моделей выбран вне каталога данных (например, общая папка `D:\Models`), из него удаляются только файлы OmniBox: GGUF, недокачанные файлы и хранилище Ollama (`blobs`, `manifests`). Чужие файлы остаются, команда их перечисляет; опустевший каталог удаляется. Модели, которые хотите сохранить, перенесите до удаления.

`ai uninstall --yes` удаляет всё без вопроса.
