# Архитектура

## Границы

`ai.cmd` запускает PowerShell 7 без профиля, затем `ai.ps1` импортирует `src/OmniBox.Ai.psm1`. Модуль читает локальный JSON, выполняет одну команду и завершается. CLI не оставляет фонового процесса. Веб-панель работает отдельной службой `omnibox-ai`, через `panel.ps1` и HttpListener.

Рабочие движки остаются отдельными Windows-службами WinSW. Они живут независимо от SSH-сеанса, а `ai` лишь отправляет start/stop и проверяет локальные API.

| Компонент | Ответственность |
|---|---|
| `web/*` | Интерфейс в браузере, отдельные страницы обзора, моделей, подключения и журналов |
| `Panel.Server.psm1` | HTTP, сессии, CSRF, очередь операций через ThreadJob |
| `Panel.Engine.ps1` | Настройки движков, каталог моделей, загрузка/выгрузка и скачивание |
| `Panel.Security.psm1` | PBKDF2, случайные session/CSRF tokens, валидация сетевой конфигурации |
| `Panel.Install.psm1` | Мастер сети/пароля, WinSW-служба панели, ACL, Firewall |
| `OpenAi.Proxy.cs` | Async HTTP relay выбранному локальному backend, SSE, Bearer auth, лимиты тела/параллельности |
| `Gateway.Helpers.psm1` | Конфигурация сетевого API, случайные ключи/hash, атомарная запись |
| `Model.Catalog.psm1` | Поиск Hugging Face и GGUF metadata по запросу пользователя |
| `gateway.json` | Порт, клиентский Base URL, выбранный backend, режим авторизации и hash ключа |
| `panel.json` | Адреса панели, порт, hash пароля и SSH-адрес |
| `ai.cmd` | Вход из PATH/CMD, запуск конкретного PowerShell после установки |
| `ai.ps1` | Аргументы без advanced parameter binding, stderr, exit code |
| `OmniBox.Ai.psm1` | Валидация конфигурации, маршрутизация CLI, управление службами, диагностика |
| `config.json` | Имена служб, пути, порты, режим эксклюзивности |
| XML WinSW | Реальные параметры моделей, память, контекст, простой, журналы, тип запуска |
| `llama-server` PrismML | Bonsai PQ2, OpenAI API, авто-сон |
| Ollama | Обычные модели Ollama, собственный API и CLI, keep-alive |

В этой версии XML — источник истины для параметров сервера. JSON **не дублирует** контекст и idle-timeout: иначе два набора настроек могли бы разойтись. Если порт изменён в XML, обнови соответствующий `base_url` в JSON.

Команды контекста редактируют XML с проверкой идентификатора службы и атомарной заменой. `context` только сохраняет, `restart --context` явно останавливает/перезапускает процесс. CLI контекста сохраняет остальные аргументы; веб-панель дополнительно меняет явно выбранные параметры запуска и простой. Предыдущий XML и состояние ожидающего применения изменения находятся рядом с XML, вне каталога оболочки; обновление `ai` не теряет историю отката.

`scripts/build-setup.ps1` собирает `dist/install-omnibox-ai.ps1` из исходников и шаблона. Скрипт содержит сжатый пакет, проверяет hash и запускает мастер прямо на ПК. Мастер реализован в `Setup.Helpers.psm1`, вопросы тестируются отдельно. Для скачивания из приватного репозитория `scripts/get-install.ps1` запрашивает GitHub-токен в память; локальный установочный пакет работает без сети. Движки не устанавливаются.

## Конфигурация

`config.example.json` содержит проверенные пути текущей установки. Установщик один раз копирует его в `config.json`; при обновлении локальная конфигурация сохраняется. `config.json` исключён из git. Альтернативный файл задаётся переменной `OMNIBOX_AI_CONFIG`:

```powershell
$env:OMNIBOX_AI_CONFIG = 'C:\tools\ai\config.json'
```

Схема 1 принимает локальные HTTP-адреса, типы `prism`/`ollama`, конкретные имена служб без wildcard. Разным backend запрещено ссылаться на одну службу. Таймауты — целые числа 1..3600 с.

`default_backend` влияет на start/restart/endpoint/logs, но не на команды Ollama. `ai stop` без аргумента всегда останавливает все настроенные службы.

## Эксклюзивность и сбои

Управляемые start/stop/restart/context/restore защищены системным mutex. При start сначала проверяется целевая служба. Затем останавливаются другие службы, запускается выбранная и ожидается её API. Если остановка другого сервера не удалась, новый сервер не запускается.

Изменение XML сохраняет один предыдущий файл `.ai-previous` и JSON истории с SHA256 и флагом pending. Последовательные неприменённые изменения не затирают исходный XML. Успешная готовность API снимает pending. При сбое запуска ожидающего изменения выполняется stop, восстановление и, только для ранее работавшего выбранного сервера, start прежних настроек. Ошибка исходной команды сохраняется. `ai restore` использует ту же историю.

Каждый файл записывается атомарно, а ошибка записи контекста приводит к возврату сохранённых байтов файлов. Это не транзакционная файловая система: аварийное отключение питания между заменой XML и истории может оставить несовпадение hash. Тогда ai откажется от автоматической перезаписи; нужны проверка файлов и ручное восстановление. Откат не покрывает ошибки генерации после готовности API.

Это **не GPU-планировщик** и не запрет параллельной нагрузки. Сторонний запуск, `Start-Service`, ручной `ollama serve`, загруженные неуправляемые процессы находятся вне контроля программы.

## Проверки

Тесты выполняют настоящий PowerShell-парсер и модуль. Windows-службы и HTTP заменяются адаптерами, поэтому аппаратная интеграция не имитируется заявлением «всё проверено». Передача native-аргументов дополнительно проверяется через настоящий дочерний процесс PowerShell с Unicode, пробелами, флагами, пустым аргументом и ненулевым exit code.

Тестовые проверки не запускают/останавливают службы и не требуют скачанной модели. Установщик следует проверить на реальной Windows повышенной SSH-сессии после получения проекта.

## HTTP и нагрузка

Панель слушает только явно заданные IPv4/DNS hosts. Каждый POST проходит Origin-проверку, изменяющие операции дополнительно требуют сессию и CSRF token. Пароль проверяется PBKDF2-SHA256; после шести неверных попыток адрес блокируется на пять минут. Cookie HttpOnly/SameSite Strict, сессия ограничена восемью часами; сессии исчезают после перезапуска панели. HTTP требует доверенной LAN/VPN или SSH-туннеля.

Маршруты статических файлов и операций фиксированы. Произвольного исполнения команд и чтения файлов через API нет. JSON ограничен 16 КиБ, модели GGUF выбираются из каталога текущей модели. Скачивание GGUF допускает прямую HTTPS-ссылку Hugging Face, исключает перезапись и проверяет заголовок/необязательный SHA256. Совместимость определяет runtime.

Долгие операции выполняются в ThreadJob: максимум одна операция управления и одно скачивание одновременно. Загрузка в память сериализована mutex вместе с CLI. Скачивание не держит mutex, поэтому отдельная команда остановки остаётся доступной. Исключения операций возвращаются в журнал результатов.

HttpListener ожидает запрос без периодического опроса моделей/GPU. Браузер опрашивает метаданные раз в восемь секунд только в видимой вкладке. GPU запрашивается при входе и ручном обновлении. Панель не генерирует запросов к модели при проверке статуса; остановленный backend не опрашивается.

API чата остаётся отдельным от интерфейса панели. HTTP-вход `/v1/*` на порту панели (18090), а при отдельной настройке также на дополнительном порту, через OpenAi.Proxy.cs передаёт OpenAI-маршруты выбранному loopback backend, без перевода модели/протокола. HttpClient/async Tasks выполняют запросы вне PowerShell-потока панели. Ответы SSE пересылаются порциями с Flush; до 8 клиентов, 8 МиБ тела, 30 минут. Цикл не запускает Windows-службы; ключ клиента хешируется и не передаётся backend. Для собственного ключа движка есть отдельный upstream_api_key. URL назначения обязан быть loopback HTTP, redirects отключены. Административные/native Ollama маршруты не публикуются. Ключ API не совпадает с паролем панели. Изменение ключа относится к новым запросам. Поиск каталога выполняется в отдельном ThreadJob; нет периодического обновления моделей/источников. [Сетевой API](model-api.md), [каталог](models.md). TLS завершает NAS; HTTPS reverse proxy поддерживается через явно заданные `public_origin` и `trusted_proxy_addresses`. Headers доверяются только конкретным IP NAS. Внешний origin проверяется по схеме/authority, Cookie имеет Secure; HTTPS-сессия не принимается по прямому HTTP. Заголовок X-Forwarded-For используется только если содержит один IP. Размещение панели под URL-префиксом не поддерживается; ей нужен отдельный домен в корне `/`. [Конфигурация NAS](reverse-proxy.md).
