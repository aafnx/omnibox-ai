# OmniBox AI

Универсальная панель со светлой, тёмной и системной темами управления локальными ИИ-серверами на Windows. Версия **0.13.0**. Открывай её с ноутбука или смартфона, запускай движки, меняй настройки и управляй загрузкой моделей. Для работы с нейросетью используется отдельный клиент через API.

## Возможности

- Запуск, остановка и перезапуск серверов; **Остановить все серверы**.
- Загрузка и выгрузка моделей, скачивание Ollama-моделей и GGUF на ПК.
- Контекст и время простоя; для PrismML — GPU layers, эксперты MoE в RAM, Flash Attention, кванты KV-кеша, KV на GPU, потоки, mlock/mmap, batch, Thinking и сэмплинг (temperature, top-k/p, min-p, штрафы, лимит токенов, seed).
- Сохранение параметров для следующего запуска или применение сейчас, с откатом при ошибке запуска.
- Отсчёт до выгрузки и выбор размещения модели RAM/VRAM.
- Оформление по OMNIBOX Brandbook 1.0, оригинальные SVG/фавикон и локальные шрифты Inter.
- Индикаторы запуска; мониторинг CPU/RAM/GPU/VRAM и доступных температур при открытой панели; при остановленных серверах — снимок по открытию панели или кнопке «Обновить данные».
- Текущая активность модели, метаданные запросов и input/output/total по сеансам без содержимого.
- Явные поля OpenAI Base URL, Model и API key для Jan/Pi; поддержка HTTPS reverse proxy на NAS.
- Отдельный пароль панели; `ai access` показывает адреса, `ai password reset` восстанавливает вход.
- Один управляемый движок, одна выбранная модель и одна генерация одновременно.

## Движки

| Движок | Служба в текущей конфигурации | API на ПК |
|---|---|---|
| **PrismML** (`llama-server`, включая Bonsai PQ2 и обычные GGUF) | `bonsai` | `http://127.0.0.1:18080/v1` |
| Ollama | `ollama` | `http://127.0.0.1:11434/v1` |

Панель управляет отдельными движками. Сетевой OpenAI API по пути `/v1` на порту панели (18090) передаёт запросы выбранному движку; форматы моделей не переводятся. Имена служб и пути задаются в `config.json`. Панель называет движки по runtime — PrismML и Ollama; служба PrismML исторически называется `bonsai`, и в CLI работают оба имени: `ai start prismml` и `ai start bonsai`. Совместимые XML-профили запуска читаются самой программой; WinSW не используется.

Требуются Windows, PowerShell **7.4+** и установленные исполняемые файлы движков. Установщик переводит существующие службы на встроенный service runtime, проверяет его запуск/остановку и сохраняет прежние файлы в backups. Драйверы и модели не скачиваются автоматически. Python, Node.js, Docker и WSL для работы панели не нужны.

## Установка одним скриптом на ПК

Рекомендуемый способ — GitHub CLI на серверном ПК. Git не требуется. Выполни команды в повышенной SSH-сессии PowerShell 7 под тем Windows-пользователем, который будет обновлять программу.

Один раз установи `gh`:

```powershell
winget install --id GitHub.cli --exact --source winget
```

Если после установки команда `gh` не найдена, переподключись по SSH. Затем войди:

```powershell
gh auth login --hostname github.com --git-protocol https --web
```

Войди в аккаунт с доступом к `aafnx/omnibox-ai`. URL и код подтверждения из SSH можно использовать в браузере ноутбука или телефона. Для CLI скачивание выполняет `gh`. Установщик также подключает этот вход к веб-панели через Windows DPAPI и защищённый ACL, поскольку панель работает от SYSTEM. Позже можно войти отдельно по коду прямо в панели. [Установка gh](https://github.com/cli/cli/blob/trunk/docs/install_windows.md), [авторизация](https://cli.github.com/manual/gh_auth_login).

Установка или первое обновление старой версии — одна строка:

```powershell
& { $ErrorActionPreference='Stop'; $p=gh api --hostname github.com 'repos/aafnx/omnibox-ai/contents/dist/install-omnibox-ai.ps1?ref=main' | ConvertFrom-Json; if($LASTEXITCODE -ne 0 -or $p.encoding -ne 'base64'){throw 'Не удалось скачать установщик'}; $f=Join-Path $env:TEMP ('omnibox-ai-'+[guid]::NewGuid().ToString('N')+'.ps1'); try{[IO.File]::WriteAllBytes($f,[Convert]::FromBase64String($p.content)); & $f}finally{if(Test-Path -LiteralPath $f){Remove-Item -LiteralPath $f -Force}} }
```

Для установок с доступной командой `ai update` обновление через CLI:

```powershell
ai update
```

Команда использует текущую авторизацию `gh`, скачивает `main` и обновляет приложение без повторных вопросов. Учётная запись должна по-прежнему иметь доступ к репозиторию. Настройки NAS, панели, моделей и ключей сохраняются. На время обновления службы останавливаются, панель запускается снова; ИИ-движки остаются остановленными. Фоновых проверок обновлений нет.

Версии и откат на конкретную версию:

```powershell
ai update --list     # доступные версии с примечаниями, отмечены последняя и установленная
ai update 0.9.5      # установить указанную версию: обновление, переустановка или откат
```

Пример вывода `ai update --list`:

```text
Доступные версии OmniBox AI:
  0.9.6  (выбор версии: ai update --list и ai update <версия>)  — последняя, установлена
  0.9.5  (CI, транзакционная установка с автооткатом)
  0.9.4  (миграция служб через Win32_Service.Change; без автоотката установки)
```

Список ведётся в `releases.json`. Устанавливать поверх текущей системы можно версии начиная с 0.9.4; более старые несовместимы с текущими службами. Настройки при откате сохраняются.

Если нужен ручной ввод токена: `ai update --token` (также `ai update 0.9.5 --token`). Без установленного `gh` загрузчик также использует ввод токена. Если `gh` найден, но доступ не работает, программа завершает скачивание с ошибкой до запуска установщика: проверь `gh auth status --hostname github.com`, при необходимости `gh auth switch --hostname github.com --user aafnx`.

Ручной способ через токен описан в [инструкции установки](docs/install.md).

Мастер спросит папку (`C:\tools\ai`), сервер по умолчанию, контекст, запуск сейчас, адрес/порт панели, разрешённые сети и пароль, а также порт/Base URL сетевого API и использование ключа. Подтверждения: `yes/no` или `y/n`; Enter сохраняет предложенное значение. Proxy можно оставить выключенным до настройки NAS. По умолчанию ИИ-сервер не запускается. Панель устанавливается отдельной службой `omnibox-ai` с автоматическим запуском.

После установки открой адрес, показанный мастером. Для текущего OmniBox при выборе `192.168.1.77` и стандартного порта: **`http://192.168.1.77:18090`**. Для API клиентов на этом ПК используйте `http://192.168.1.77:18090/v1`, либо после настройки NAS `https://llm.fnx.red/v1`. SSH-туннель не требуется. Для панели доступны LAN/VPN или HTTPS через NAS. Подробности: [установка и обновление](docs/install.md), [веб-панель и подключение](docs/web-panel.md).

## Ресурсы и простой

Панель не загружает модель при открытии. Мониторинг ресурсов включается при работающем движке и видимой вкладке, примерно раз в 3 секунды, и прекращается при остановке/сне модели или скрытии вкладки. В простое нет фонового сэмплера. Сама служба панели занимает CPU/RAM PowerShell/.NET. Мониторинг CPU/RAM использует Windows, внешние программы не нужны. Температура CPU исключена. Для GPU показывается скорость вентиляторов в %, если драйвер сообщает её.

Движки с ручным запуском остаются остановленными до команды пользователя. Таймаут простоя задаётся в настройках, для текущей установки — **30 минут**. Автоматическая выгрузка реализована самими движками; новый запрос к работающему серверу может загрузить модель снова. **Остановить все серверы** полностью останавливает настроенные движки и оставляет панель доступной.

Управляемый запуск последовательно останавливает другие движки даже при старом `exclusive:false`. Ollama/PrismML ограничиваются одной моделью/слотом. API принимает только выбранную модель, второй одновременный запрос отклоняется. Сторонние процессы и прямой запуск служб находятся вне управления программы.

## Разработка и проверки

Изменения идут через отдельные ветки и pull request в `main`. CI (`.github/workflows/ci.yml`) запускает все наборы на `windows-latest` и `ubuntu-latest`; PR сливается только при зелёном CI.

```powershell
pwsh -NoProfile -File .\tests\test.ps1
pwsh -NoProfile -File .\tests\update_test.ps1
pwsh -NoProfile -File .\tests\install_flow_test.ps1
pwsh -NoProfile -File .\tests\native_host_test.ps1
pwsh -NoProfile -File .\tests\scm_test.ps1
$env:OMNIBOX_AI_REAL_INSTALL_TEST='1'; pwsh -NoProfile -File .\tests\real_install_test.ps1   # только на одноразовой машине
```

```powershell
python -m unittest discover -s tests -p http_test.py -v
```

`real_install_test.ps1` выполняет настоящую установку со службой `omnibox-ai`, принудительными сбоями обновления и откатом; он запускается только по флагу и отказывается работать там, где omnibox-ai уже установлен. `native_host_test.ps1` и `scm_test.ps1` на Windows регистрируют временные службы и требуют повышенного PowerShell; на других ОС реальные SCM-проверки пропускаются. `scm_test.ps1` проверяет запуск/остановку через SCM, `Win32_Service.Change`, аварийное завершение дочернего процесса и очистку всего дерева процессов.

Python нужен только для HTTP-тестов. Поведение JS-интерфейса дополнительно проверяется `node tests/web_test.cjs` с адаптером DOM; это не визуальный браузерный тест. Набор HTTP-тестов проверяет настоящий HTTP-сервер PowerShell, вход, CSRF/Origin, ограничения запросов, журналы и фоновые операции с тестовым адаптером движков. Тесты управления проверяют XML, откат, эксклюзивность и модели без GPU. ACL и Firewall на серверном ПК проверяются после установки.

Версия задаётся только в файле `VERSION`; список файлов пакета — в `package.psd1`. После изменения исходников пересобери единый установочный файл, иначе `tests/test.ps1` и CI сообщат о расхождении `dist/`:

```powershell
pwsh -NoProfile -File .\scripts\build-setup.ps1
```
