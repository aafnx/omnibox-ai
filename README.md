# OmniBox AI

`ai` — единая команда управления ИИ-серверами на игровом ПК с Windows.
Версия **0.2.0**, PowerShell **7.4+** на ПК, без Python, Node.js и постоянно работающего управляющего процесса.

```powershell
ai start
```

```powershell
ai status
```

```powershell
ai stop
```

## Что управляется

| Имя | Движок | Существующая служба | Локальный API |
|---|---|---|---|
| `bonsai` | `llama-server` из форка PrismML | `bonsai` через WinSW | `http://127.0.0.1:18080/v1` |
| `ollama` | Обычный Ollama | `ollama` через WinSW | `http://127.0.0.1:11434/v1` |

Это **два разных сервера**, не две команды одного движка. `ai` скрывает различия в управлении службами, но не подменяет форматы моделей и не переводит протоколы API. Для Bonsai 2 PQ2 нужен движок PrismML; команды Ollama обслуживают только Ollama.

Программа работает поверх существующей, уже проверенной установки. Она **не устанавливает и не обновляет движки, WinSW, драйверы или модели**, не переносит службы в Планировщик. XML меняется только по явной команде изменения контекста, с резервной копией.

## Установка одним скриптом через SSH

Скачай [install-omnibox-ai.ps1](dist/install-omnibox-ai.ps1) через **Download raw file** в GitHub в `Downloads` на ноутбуке. Скрипт содержит весь пакет: ему не нужны GitHub-токен, Git, отдельный ZIP или скачивание исходников с приватных raw-URL.

В обычном PowerShell **на ноутбуке** выполни одну команду:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\install-omnibox-ai.ps1" -Remote
```

Он сам отправит себя на `avoq@192.168.1.77` через SCP с ключом `.ssh\id_ed25519_omnibox`, запустит установку через SSH и удалит переданную временную копию после успеха. На ноутбуке достаточно штатного Windows PowerShell 5.1; на OmniBox нужен уже установленный PowerShell 7.4+.

Установка/обновление — в `C:\tools\ai`. JSON сохраняется, службы не перезапускаются, контекст сам по себе не меняется. Добавляется пользовательский PATH и небольшой PATH-блок в профиль PowerShell 7 (с backup, без замены промпта), чтобы новая SSH-сессия находила `ai` без перезапуска `sshd`.

После установки переподключись по SSH и проверь:

```powershell
ai help
```

```powershell
ai status
```

Если файл уже находится на OmniBox, можно выполнить его прямо в повышенной SSH-сессии **без `-Remote`**. Это та же установка, без SCP. Подробности и вариант ZIP — в инструкции ниже.

Подробности: [установка и обновление](docs/install.md).

## Команды

| Команда | Результат |
|---|---|
| `ai start` | Запустить сервер по умолчанию — Bonsai |
| `ai start bonsai` | Остановить Ollama и запустить Bonsai |
| `ai start ollama` | Остановить Bonsai и запустить Ollama |
| `ai stop` | Остановить оба настроенных сервера |
| `ai stop bonsai` | Остановить только Bonsai |
| `ai restart bonsai` | Перезапустить Bonsai |
| `ai start bonsai --context 128k` | Запустить остановленный Bonsai с новым контекстом |
| `ai restart bonsai --context 128k` | Применить новый контекст сейчас, с перезапуском |
| `ai context bonsai` | Посмотреть сохранённый в XML контекст |
| `ai context bonsai 192k` | Сохранить 192К для следующего запуска, без перезапуска |
| `ai status` | Службы, API, модель, контекст, сон, видеопамять |
| `ai logs bonsai` | Последние 60 строк err/out/wrapper журналов |
| `ai logs bonsai 100 err` | Последние 100 строк stderr |
| `ai endpoint bonsai` | Адрес OpenAI-совместимого API |
| `ai config` | Путь и содержимое конфигурации |
| `ai ollama --version` | Запустить настоящий CLI Ollama |
| `ai ollama pull MODEL` | Передать `pull MODEL` в Ollama |
| `ai help` | Справка |

Для удобства `ai pull`, `ai run`, `ai list`, `ai ps`, `ai show`, `ai create`, `ai cp`, `ai rm`, `ai push` — сокращения **команд Ollama**, даже если `default_backend` равен `bonsai`. Они **не запускают и не переключают службы автоматически**. Перед использованием серверных команд явно выполни `ai start ollama`. Например:

```powershell
ai start ollama
```

```powershell
ai ollama list
```

`ai start`/`stop`/`restart` требуют повышенных прав. Просмотр журналов, справка, конфигурация и обычный CLI Ollama не требуют повышения от самой оболочки (права на файлы/службы определяет Windows).

Все примеры предназначены для копирования **по одному блоку**, каждый блок состоит из одной физической строки.

## Контекст для загрузки модели

```powershell
ai restart bonsai --context 128k
```

Размеры: `32k = 32768`, `128k = 131072`, `192k = 196608`. Можно передать точное число токенов. Значение сохраняется в XML службы; перед заменой создаётся точная резервная копия. Порт, модель, cache q8, простой и тип запуска остаются прежними.

`ai context bonsai 128k` только сохраняет настройки. Если модель уже загружена с 192К, она продолжит работать с 192К до перезапуска. `ai start --context ...` откажется менять работающий сервер, предлагая явный `restart`.

Для Ollama:

```powershell
ai restart ollama --context 32k
```

Это меняет **серверный default** `OLLAMA_CONTEXT_LENGTH`. Параметр `num_ctx` конкретной модели/запроса может переопределять его. Для запущенной модели проверяй `ai ollama ps`, а для Bonsai — `ai status`. Большой контекст не гарантирует, что модель поместится в память; программа сама не уменьшает выбранный размер.

## Игровой режим и простой

Перед игрой:

```powershell
ai stop
```

- `exclusive: true` по умолчанию: управляемый запуск одного сервера останавливает другой. Если остановка другого сервера не удалась, новый не запускается.
- `ai` ничего не запускает при загрузке Windows. Существующие службы должны оставаться `Manual`; проверить можно через `ai status`.
- Текущий Bonsai: PQ2, контекст **196608 (192К)**, один слот, KV-cache `q8_0`, `--sleep-idle-seconds 1800`.
- Текущий Ollama: `OLLAMA_KEEP_ALIVE=30m`. Модели загружаются по запросу.
- Таймеры реализованы **в самих движках**, а не в `ai`. Программа не изменяет и не перепроверяет эти параметры автоматически; фактический источник — XML служб.
- При простое сервер остаётся работающим и может снова загрузить модель по запросу. `ai stop` полностью останавливает сервер; новый запрос сам службу не запустит.
- `ai status` не загружает Bonsai: используется `/props`. Остановленные серверы вообще не опрашиваются.
- Автоматического определения запущенной игры в версии 0.2.0 нет. Сначала `ai stop`, затем игра. Команды напрямую через `Start-Service`, сторонние процессы и запросы к уже запущенным серверам не блокируются оболочкой.

Ранее на RTX 5080 проверены запуск Bonsai с 192К и короткая генерация: занято 15020 MiB, свободно 958 MiB по `nvidia-smi`. Это не тест заполненного контекста 192К и не гарантия отсутствия OOM на длинных запросах.

## Клиенты на ноутбуке

Сервер слушает только loopback. Для Bonsai открой отдельный терминал **на ноутбуке**:

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 11435:127.0.0.1:18080 -i "$env:USERPROFILE\.ssh\id_ed25519_omnibox" avoq@192.168.1.77
```

Jan/Pi на ноутбуке используют `http://127.0.0.1:11435/v1`, имя модели `bonsai-2-27b`. Туннель держится, пока открыт SSH-процесс. Внешнее подключение — через уже настроенную домашнюю сеть/VPN и доступный SSH-адрес; `192.168.1.77` — пример локального адреса.

Для Ollama можно отдельно пробросить `11436:127.0.0.1:11434`, клиентский base URL будет `http://127.0.0.1:11436/v1`. `ai endpoint` выводит **адрес на самом ПК**, не адрес клиентского туннеля.
