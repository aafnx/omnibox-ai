# AGENTS.md — правила для ИИ-агентов

Документ для ИИ-агентов (Claude Code, Codex, Copilot и др.), которые меняют этот репозиторий. Он описывает проект, его неизменные требования и порядок работы. Подробности — в `README.md`, `docs/architecture-go.md`, `docs/roadmap.md`. При расхождении код и тесты важнее документации: найденное расхождение исправь или сообщи о нём.

## Проект

**OmniBox AI** — панель и OpenAI-совместимый API для локальных ИИ-движков на домашнем ПК (Windows, RTX 5080 16 ГБ VRAM, 32 ГБ RAM; Linux — следующая платформа). Версия задаётся в файле `VERSION`.

Программа — один Go-бинарник `omnibox` для Windows и Linux:

- **Служба `omnibox`** (`omnibox serve`): панель (`internal/panel`, интерфейс из `web/`, встроен в бинарник) и `/v1` (`internal/gateway`) на одном порту (по умолчанию 8800).
- **Движки** — отдельные службы ОС `omnibox-prismml` и `omnibox-ollama` (`omnibox engine <движок>`, `internal/host`): PrismML `llama-server` (Bonsai PQ2 и обычные GGUF) и Ollama на loopback (8801, 8802). Оба движка остаются.
- **Настройки** — один `config.json` (`internal/config`); пишет только служба, атомарно, через `config.Store`.
- **Клиенты API:** Jan, Pi, Open WebUI. Доступ только из LAN и WireGuard; HTTPS завершает reverse proxy на Synology NAS (`https://llm.fnx.red`). Wake-on-LAN — через Home Assistant.

PowerShell-версия удалена из `main` по решению владельца; последняя — ветка `powershell-0.17.1`. Её не исправляют и к ней не возвращаются; совместимость с её файлами не нужна (чистая установка). Ещё не перенесено (см. этап G в `docs/roadmap.md`): установщик и обновление, CLI `ai`, перевод `web/app.js` на ответы Go-сервера, пользовательская документация.

**Зависимости:**
- ядро работает без установки чего-либо на ПК: один бинарник;
- Go-модули — только MIT, BSD или Apache-2.0, без cgo, с версиями в `go.sum`; в PR указывай, зачем нужна новая зависимость. Версия Go — из `go.mod`; `golang.org/x/sys` не новее версии, совместимой с этой версией Go;
- Python, Node.js и другие программы на ПК допустимы только для необязательных возможностей (например, расширенный мониторинг): без них панель работает и показывает, что компонент не установлен;
- Docker, WSL и WinSW для работы ядра не требуются. Node используется в тесте интерфейса.

## Принципы, которые нельзя нарушать

1. **Минимальная нагрузка в простое.** Никаких фоновых таймеров опроса служб, GPU и моделей. Всё вычисляется по запросу пользователя или клиента; периодическая телеметрия — только при открытой вкладке и работающем движке; разовый снимок — по действию пользователя (вход, возврат на вкладку, «Обновить данные»).
2. **Модель выбирается в панели.** Запрос к API не может сам загрузить другую модель или запустить остановленный сервер. Любое автопереключение — только отдельной опцией, выключенной по умолчанию.
3. **Работа без API key разрешена.** Переключатель ключа сохраняется.
4. **После «Остановить» сервер остаётся остановленным** при любом восстановлении: откат, автоперезапуск, обновление.
5. **Одна модель и одна генерация одновременно.** Параллельные запросы ждут в очереди `/v1`, привязанной к поколению: после остановки или смены модели запрос из очереди не выполняется на другой модели.
6. **Обновление не теряет пользовательские данные:** пароль панели, API key, адреса NAS, `config.json`, модели. Любой сбой установки откатывается автоматически.

## Структура

| Путь | Назначение |
|---|---|
| `VERSION` | Единственный источник версии (x.y.z); Go читает его через `go:embed` (`version.go`). Не вписывай версию в код |
| `cmd/omnibox` | Точка входа: `serve`, `engine`, `version` |
| `internal/config` | Схема и проверка `config.json`, правила настроек движков, откат `previous`/`pending`, `Store` |
| `internal/control` | Запуск, остановка, применение и откат настроек; фоновые операции панели |
| `internal/gateway` | `/v1`: ключ, очередь и поколения (F2), прокси, учёт токенов, журналы запросов |
| `internal/host` | Хост службы движка: Job Object (Windows) или группа процессов (Linux), журналы, `runtime.json` |
| `internal/panel` | HTTP-панель: вход (PBKDF2), сессии, CSRF, Origin/Host, reverse proxy, статика |
| `internal/engine` | Аргументы запуска движков, модели, проверки API, `runtime.json` |
| `internal/status`, `internal/telemetry` | Статус движков и ресурсы по запросу |
| `internal/storage` | Объём журналов, движков и моделей, диски, очистка по сроку хранения |
| `internal/enginemgr` | Версии движков из выпусков GitHub: список, скачивание, проверка, распаковка |
| `internal/catalog` | Поиск GGUF на Hugging Face, скачивание моделей с докачкой |
| `internal/platform` | Службы ОС (SCM, systemd), чтение и атомарная запись файлов; `*_windows.go` и `*_unix.go` |
| `web/` | Интерфейс панели. Оформление — по брендбуку `docs/brand/` |
| `tests/web_test.cjs` | Поведение интерфейса через DOM-адаптер |
| `docs/` | Архитектура (`architecture-go.md`), план (`roadmap.md`), брендбук |

Программа не должна копить файлы на ПК: всё, что пишется на диск (журналы, временные файлы), имеет ротацию, срок хранения или удаление. Очистка — только при запуске службы, установке или по действию пользователя, без таймеров.

## Порядок работы

- **Ветки и PR.** Не коммить напрямую в `main`. Одна задача — одна ветка и pull request; сливать только при зелёном CI.
- **Коммиты:** `тип: описание`, где тип — `feat`, `fix`, `docs`, `test`, `ci`, `build`, `refactor`. К релизному коммиту допиши версию в скобках: `feat: ... (0.18.0)`.
- **Каждая пользовательская версия:** обнови `VERSION`, добавь раздел `## x.y.z — дата` в начало `CHANGELOG.md`, поправь `Версия **x.y.z**` в `README.md` и строку «Состояние на …» в `docs/roadmap.md`, добавь `### x.y.z` в «Выполнено по версиям». Иначе упадёт `TestVersionIsTheSingleSource`.
- **Документация:** при изменении поведения обнови `docs/` и `README.md`. Тексты для пользователя пишутся на русском.
- **План (`docs/roadmap.md`) обновляется в каждом PR — без исключений:**
  - сделанное запиши в «Выполнено по версиям» (для PR без новой версии — в запись текущей версии);
  - отметь выполненные или частично выполненные пункты в разделах 1–4;
  - новые задачи, найденные проблемы и решения владельца добавь в соответствующие разделы; устаревшее убери.
- **Объём изменений:** минимально необходимый для задачи; не переформатируй чужой код без нужды.

## Стиль кода

- Пиши как окружающий код: те же имена, плотность и идиомы. `gofmt` обязателен.
- **Языки:** сообщения пользователю (ошибки панели, вывод команд, UI) — на русском; ошибки `/v1` для клиентов — на английском в формате OpenAI; комментарии в коде и сообщения коммитов — на английском. Комментарий объясняет «почему», а не пересказывает код.
- **Платформы:** код для одной ОС — в файлах `*_windows.go` / `*_unix.go` за интерфейсом в `internal/platform` или своём пакете; сборка обеих ОС не должна ломаться (`GOOS=windows go vet ./...`).
- **Файлы:** настройки и состояние пиши через `platform.WriteAtomic`, читай через `platform.ReadShared` (на Windows читатель не мешает атомарной замене). `config.json` меняется только через `config.Store.Update`.
- **Окончания строк** задаёт `.gitattributes`: всё LF, кроме `.ps1`/`.cmd` (будущие скрипты установки для Windows PowerShell) — CRLF.
- **Интерфейс** следует брендбуку OMNIBOX (`docs/brand/README.md`, PDF рядом): палитра Void/Deep Night/Signal, акцент Iris, градиент Ice → Iris → Ember без смены порядка, без синего и мигания; логотип не растягивать и не перекрашивать. В вебе без CDN: шрифты и картинки лежат локально и встраиваются в бинарник.

## Безопасность

- Служба работает от SYSTEM (root на Linux). Нельзя добавлять маршруты, которые выполняют произвольные команды или читают произвольные файлы; маршруты и статика фиксированы, операции панели — структурированные поля, без командной строки.
- Изменяющие запросы требуют сессию, CSRF и проверку Origin/Host. `X-Forwarded-*` принимаются только от IP из `panel.trusted_proxies`.
- Ключ API проверяется до любых обращений к службам и движку.
- Содержимое запросов к `/v1` записывается только при явном выборе владельца (`storage.request_log: content`), в отдельный `content.jsonl`; по умолчанию — только метаданные.
- Секреты (пароль, API key, токены) не попадают в журналы, ответы API, сообщения об ошибках и аргументы командной строки. Хранятся только hash (PBKDF2 для пароля, SHA256 для ключа).
- Прокси `/v1` ходит только на loopback-адреса, без редиректов; ключ клиента не передаётся движку.
- Не ослабляй права на каталоги установки и правила Firewall без явной просьбы владельца.

## Тесты

Тесты — стандартный `go test` и `tests/web_test.cjs`. Службы ОС, движки и `nvidia-smi` в тестах заменяются адаптерами (`platform.FakeServices`, `httptest`-движки, тестовый бинарник как поддельный движок).

```sh
gofmt -l . ; go vet ./... ; GOOS=windows go vet ./... ; go test ./...
node tests/web_test.cjs
```

- Новое поведение покрывай тестом в пакете, который его реализует. Исправление ошибки — с тестом, который падал без исправления.
- Тест не должен зависеть от разделителя путей, окончаний строк checkout, сети, GPU или скачанной модели; конкурентный код проверяй с `-race`.
- Никогда не регистрируй настоящие службы в обычных тестах и не запускай тесты, меняющие службы, на серверном ПК пользователя.

## CI

`.github/workflows/ci.yml` запускается на push в любую ветку и на pull request:

- **Windows** (`windows-latest`): `go vet`, `go test` (в том числе хост движка с Job Object), сборка `omnibox.exe`.
- **Linux** (`ubuntu-latest`): `gofmt`, `go vet` для обеих ОС, `go test -race`, сборки для Linux и Windows без cgo, `web_test.cjs`.

Перед push прогони проверки локально. Красный CI — это работа, а не «флейк»: найди причину. Тесты нельзя отключать, пропускать или ослаблять ради зелёного CI.

## Готово, когда

- [ ] Тесты для нового поведения добавлены, все проверки зелёные локально и в CI (Windows и Linux).
- [ ] `VERSION`, `CHANGELOG.md`, `README.md` и нужные `docs/` обновлены для пользовательских изменений.
- [ ] План `docs/roadmap.md` обновлён: выполненное отмечено, новые задачи и решения добавлены.
- [ ] Принципы не нарушены: нет фонового опроса, нет автозапуска, секреты не утекают, настройки сохраняются при обновлении.
- [ ] Изменения в отдельной ветке; PR описывает, что сделано и как проверено. Проверку на реальном серверном ПК выполняет владелец.
