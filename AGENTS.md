# AGENTS.md — правила для ИИ-агентов

Документ для ИИ-агентов (Claude Code, Codex, Copilot и др.), которые меняют этот репозиторий. Он описывает проект, его неизменные требования и порядок работы. Подробности — в `README.md`, `docs/architecture.md`, `docs/roadmap.md`. При расхождении код и тесты важнее документации: найденное расхождение исправь или сообщи о нём.

## Проект

**OmniBox AI** — панель и CLI для управления локальными ИИ-движками на домашнем Windows-ПК (RTX 5080 16 ГБ VRAM, 32 ГБ RAM). Версия задаётся в файле `VERSION`.

- **Движки:** PrismML `llama-server` (Bonsai PQ2) и Ollama. Оба остаются; каждый — отдельная Windows-служба.
- **Панель:** служба `omnibox-ai` (`panel.ps1` → `src/Panel.Server.psm1`, HttpListener, порт 18090) с веб-интерфейсом из `web/`.
- **OpenAI-совместимый API** `/v1` на порту панели: C#-прокси `src/OpenAi.Proxy.cs` передаёт запросы выбранному loopback-движку.
- **CLI** `ai` (`ai.cmd` → `ai.ps1` → `src/OmniBox.Ai.psm1`).
- **Service runtime:** собственный `src/Service.Host.cs`, компилируется на ПК штатным `csc.exe` из .NET Framework. Job Object держит всё дерево процессов движка.
- **Установщик:** `install.ps1`, собирается в самодостаточный `dist/install-omnibox-ai.ps1`. Обновление — `ai update` (через `gh`) или из веб-панели (временная служба `scripts/update-worker.ps1`).
- **Клиенты API:** Jan, Pi, Open WebUI. Доступ только из LAN и WireGuard; HTTPS завершает reverse proxy на Synology NAS (`https://llm.fnx.red`). Wake-on-LAN — через Home Assistant.

Стек: **PowerShell 7.4+** и встроенный **C#** (`Add-Type` / `csc.exe`), фронтенд на чистом JS/CSS без сборки. На сервере не нужны Python, Node.js, Docker, WSL, .NET SDK и WinSW — не добавляй такие зависимости в продукт. Python и Node используются только в тестах.

## Принципы, которые нельзя нарушать

1. **Минимальная нагрузка в простое.** Никаких фоновых таймеров опроса служб, GPU и моделей. Всё вычисляется по запросу пользователя или клиента; телеметрия — только при открытой вкладке и работающем движке.
2. **Модель выбирается в панели.** Запрос к API не может сам загрузить другую модель или запустить остановленный сервер. Любое автопереключение — только отдельной опцией, выключенной по умолчанию.
3. **Работа без API key разрешена.** Переключатель ключа сохраняется.
4. **После «Остановить» сервер остаётся остановленным** при любом восстановлении: откат, автоперезапуск, обновление.
5. **Одна модель и одна генерация одновременно.**
6. **Обновление не теряет пользовательские данные:** пароль панели, API key, адреса NAS, `config.json`, XML-профили движков, историю отката `.ai-previous`/`.ai-state.json`, доступ gh. Любой сбой установки откатывается автоматически.

## Порядок работы

- **Ветки и PR.** Не коммить напрямую в `main`. Одна задача или этап roadmap — одна ветка и pull request; сливать только при зелёном CI.
- **Коммиты:** `тип: описание`, где тип — `feat`, `fix`, `docs`, `test`, `ci`, `build`, `refactor`. К релизному коммиту допиши версию в скобках: `fix: ... (0.9.4)`.
- **Каждая пользовательская версия:** обнови `VERSION`, добавь раздел `## x.y.z — дата` в начало `CHANGELOG.md`, поправь `Версия **x.y.z**` в `README.md`. Иначе тест `VERSION is the single source…` упадёт.
- **`releases.json` — список версий для `ai update --list` и `ai update <версия>`.** При выпуске новой версии:
  - добавь её первой записью с `"commit": null` (такая версия ставится из `main`) и коротким примечанием;
  - у предыдущей верхней записи замени `null` на полный SHA коммита, которым она попала в `main`, — обычно это merge-коммит её PR;
  - тест сверяет, что верхняя запись совпадает с `VERSION`, а коммит каждой старой записи содержит установщик именно этой версии.

  Версии старше 0.9.4 в список не добавляй: их установщики несовместимы со службами на `Service.Host.exe`.
- **После любого изменения файлов пакета** пересобери установщик: `pwsh -NoProfile -File ./scripts/build-setup.ps1`. Тест `self-contained package matches every current source file` и CI сверяют `dist/` с исходниками.
- **Новый файл, нужный на ПК,** добавь в `package.psd1` → `Files`. Списки файлов в коде не дублируй.
- **Документация:** при изменении поведения обнови соответствующий файл в `docs/` и `README.md`. Тексты для пользователя пишутся на русском.
- **Roadmap:** выполненный пункт отметь в `docs/roadmap.md`.
- **Объём изменений:** минимально необходимый для задачи; не переформатируй чужой код без нужды.

## Стиль кода

- Пиши как окружающий код: тот же стиль имён (`Verb-AiNoun` для функций), плотность и идиомы. Модули — `Set-StrictMode -Version Latest`, скрипты — `$ErrorActionPreference = 'Stop'`.
- **Языки:** сообщения пользователю (исключения, `Write-Host`, UI) — на русском; комментарии в коде и сообщения коммитов — на английском. Комментарий объясняет «почему», а не пересказывает код.
- **Окончания строк** задаёт `.gitattributes`: `.ps1/.psm1/.psd1/.cmd` — CRLF, остальное — LF. Сборка нормализует их сама, но не смешивай окончания внутри файла.
- **C#** в `Service.Host.cs` — только C# 5 и .NET Framework 4.x (компилятор Windows). В `OpenAi.Proxy.cs` и `Inference.Stats.cs` код должен компилироваться через `Add-Type` в PowerShell 7.4.
- **Без новых внешних зависимостей** в продукте: никаких модулей из PSGallery, NuGet-пакетов, CDN в вебе. Шрифты и картинки лежат локально.

## Особенности Windows и PowerShell (частые ошибки)

- **Службы:** путь запуска менять только через `Set-AiServiceCommand` (`Win32_Service.Change` с проверкой кода и результата). `Set-Service -BinaryPathName` запрещён — его ловит тест.
- **Замки:** `Global\omnibox-ai-install-v1` (установка) и `Global\omnibox-ai-control-v1` (управление движками). Порядок захвата всегда «установка → управление». Повторный захват тем же потоком допустим: веб-worker держит оба замка и вызывает установщик в своём потоке. Управление движками — только внутри `Invoke-AiLocked`.
- **Импорт модулей:** вложенный `Import-Module ... -Force` для общих зависимостей удаляет их экспорт у вызывающего. Во вложенных модулях импортируй без `-Force` (см. комментарии в `Panel.Install.psm1` и `Install.Transaction.psm1`).
- **Пути:** `Join-Path` на Windows ставит `\`. В тестах не сравнивай пути с `/` через `-like`: строй ожидаемое значение через `Join-Path` или используй `[\\/]`.
- **Возврат массивов:** `return ,$array` вместе с `@(...)` у вызывающего даёт массив из одного массива. Возвращай массив без запятой, если вызывающий оборачивает результат в `@()`.
- **Атомарная запись:** настройки пиши через временный файл и `Move`/`Replace` (`Write-AiAtomicBytes`, `Write-AiGatewayConfig`). XML-профили разбирай с `DtdProcessing = Prohibit`.
- **Ресурсы в простое:** никаких `Start-Job`/таймеров на фоне. Долгие операции — `Start-ThreadJob`, запускаемый запросом.

## Установщик и обновления

- Всё, что меняется после снимка в `install.ps1`, выполняется внутри транзакции (`New-AiInstallTransaction` → `Add-AiInstallStep` → `Complete-AiInstallTransaction`). При ошибке — `Undo-AiInstallTransaction`. Новые шаги добавляй через `Add-AiInstallStep` с понятным именем: это даёт журнал и тестовую точку отказа `OMNIBOX_AI_INSTALL_FAIL_STEP`.
- Новый изменяемый установщиком артефакт (файл, служба, правило Firewall, реестр) должен попасть в снимок и восстанавливаться при откате.
- **Миграция настройки:** если установщик сознательно меняет пользовательскую настройку, добавь явное правило в `Get-AiInstallSettings`/`Get-AiExpectedInstallSettings` и тест на него. Иначе сверка по значениям откатит установку.
- Действия после фиксации транзакции (PATH, профиль, `ai context`, запуск сервера, gh) не откатываются — не переноси туда ничего, что может испортить установку.
- Результат установки передаётся через `$global:OmniBoxInstallResult` (`not-started`, `installed`, `rolled-back`, `rollback-failed`); веб-worker на него опирается.
- Старые установки обновляются, скачивая `dist/install-omnibox-ai.ps1?ref=main`. Сохраняй совместимость формата: строки `$expectedSha = '…'`, `$payload = '…'` и текст `OmniBox AI x.y.z payload OK`.

## Безопасность

- Панель работает от SYSTEM. Нельзя добавлять маршруты, которые выполняют произвольные команды или читают произвольные файлы; маршруты и статика фиксированы.
- Изменяющие запросы требуют сессию, CSRF и проверку Origin/Host. `X-Forwarded-*` принимаются только от IP из `trusted_proxy_addresses`.
- Секреты (пароль, API key, GitHub token) не попадают в журналы, `updates/result.json`, ответы API, сообщения об ошибках и аргументы командной строки. Хранятся только hash (PBKDF2 для пароля, SHA256 для ключа) или DPAPI.
- Прокси `/v1` ходит только на loopback-адреса, без редиректов; ключ клиента не передаётся движку.
- Не ослабляй ACL каталога установки и правила Firewall без явной просьбы владельца.

## Тесты

Тесты самописные, без Pester. Windows-провайдеры (SCM, CIM, Firewall, ACL) в обычных тестах заменены адаптерами, реальные проверки — в отдельных наборах.

| Набор | Что проверяет | Где запускается |
|---|---|---|
| `tests/test.ps1` | Ядро: CLI, XML/откат, панель, безопасность, сверка настроек, замки, версия и пакет `dist/` | Везде |
| `tests/update_test.ps1` | Веб-обновление, gh, worker | Везде |
| `tests/install_flow_test.ps1` | Настоящий `install.ps1` с адаптерами: обновление, сбой на каждом шаге, прерванная установка, конкурентный запуск | Везде |
| `tests/native_host_test.ps1` | Компиляция `Service.Host`, разбор профиля; на Windows — проба SCM | Везде (SCM — Windows, admin) |
| `tests/scm_test.ps1` | Реальный SCM: start/stop, `Win32_Service.Change`, падение дочернего процесса, дерево процессов | Windows, admin |
| `tests/real_install_test.ps1` | Настоящая установка, принудительные сбои обновления и откат | Только одноразовая Windows-машина, `OMNIBOX_AI_REAL_INSTALL_TEST=1` |
| `tests/http_test.py` | Настоящий HTTP-сервер панели и `/v1` с тестовым движком | Везде (Python 3) |
| `tests/web_test.cjs` | Поведение UI через DOM-адаптер | Везде (Node) |

Запуск:

```powershell
pwsh -NoProfile -File ./tests/test.ps1
pwsh -NoProfile -File ./tests/update_test.ps1
pwsh -NoProfile -File ./tests/install_flow_test.ps1
pwsh -NoProfile -File ./tests/native_host_test.ps1
python tests/http_test.py
node tests/web_test.cjs
```

- **Никогда** не запускай `real_install_test.ps1` и `scm_test.ps1` на серверном ПК пользователя: они регистрируют службы, в том числе `omnibox-ai`.
- На Linux (облачная сессия агента) PowerShell 7.4 ставится из релиза GitHub (`powershell-7.4.x-linux-x64.tar.gz`). Windows-проверки выполняет CI.
- Новое поведение покрывай тестом в подходящем наборе. Исправление ошибки — с тестом, который падал без исправления.
- Тест не должен зависеть от разделителя путей, окончаний строк checkout, сети, GPU или скачанной модели.

## CI

`.github/workflows/ci.yml` запускается на push в любую ветку и на pull request:

- **Windows** (`windows-latest`, admin): все наборы, реальные SCM-тесты, настоящая установка с откатом, свежая сборка `dist/` с `-CheckOnly`.
- **Linux** (`ubuntu-latest`): кроссплатформенные наборы.

Шаги выполняются независимо (`if: !cancelled()`), поэтому один прогон показывает все упавшие наборы.

Перед push прогони быстрые наборы локально. Красный CI — это работа, а не «флейк»: найди причину. Тесты нельзя отключать, пропускать или ослаблять ради зелёного CI.

## Готово, когда

- [ ] Тесты для нового поведения добавлены, все наборы зелёные локально и в CI (Windows и Linux).
- [ ] `dist/` пересобран, если менялись файлы пакета.
- [ ] `VERSION`, `CHANGELOG.md`, `README.md` и нужные `docs/` обновлены для пользовательских изменений.
- [ ] Принципы из раздела выше не нарушены: нет фонового опроса, нет автозапуска, секреты не утекают, настройки сохраняются при обновлении.
- [ ] Изменения в отдельной ветке; PR описывает, что сделано и как проверено. Проверку на реальном серверном ПК выполняет владелец после слияния.
