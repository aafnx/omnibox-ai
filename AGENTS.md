# AGENTS.md — правила для ИИ-агентов

Документ для ИИ-агентов (Claude Code, Codex, Copilot и др.), которые меняют этот репозиторий. Он описывает проект, его неизменные требования и порядок работы. Подробности — в `README.md`, `docs/architecture-go.md`, `docs/roadmap.md`. При расхождении код и тесты важнее документации: найденное расхождение исправь или сообщи о нём.

## Проект

**OmniBox AI** — панель и OpenAI-совместимый API для локальных ИИ-движков на домашнем ПК (Windows, RTX 5080 16 ГБ VRAM, 32 ГБ RAM; Linux — следующая платформа). Версия задаётся в файле `VERSION`.

Программа — один Go-бинарник `omnibox` для Windows и Linux:

- **Служба `omnibox`** (`omnibox serve`): панель (`internal/panel`, интерфейс из `web/`, встроен в бинарник) со встроенным чатом и `/v1` (`internal/gateway`) на одном порту (по умолчанию 8800). Разделы панели — Чат, Автоматизации, Модели, Сервер, Настройки; эталон вида и поведения — прототип `docs/design/prototype.html`.
- **Облако и поиск** (по действию владельца, не по таймеру): модели OpenRouter в чате и, по опции, в `/v1`; веб-поиск чата через SearXNG владельца.
- **Движки** — отдельные службы ОС `omnibox-prismml` и `omnibox-ollama` (`omnibox engine <движок>`, `internal/host`): PrismML `llama-server` (Bonsai PQ2 и обычные GGUF) и Ollama на loopback (8801, 8802). Оба движка остаются.
- **Настройки** — один `config.json` (`internal/config`); пишет только служба, атомарно, через `config.Store`.
- **Клиенты API:** Jan, Pi и другие OpenAI-совместимые клиенты. Доступ только из LAN и WireGuard; HTTPS завершает reverse proxy на Synology NAS (`https://llm.fnx.red`). Wake-on-LAN — через Home Assistant.

PowerShell-версия удалена из `main` по решению владельца; последняя — ветка `powershell-0.17.1`. Go-версия выпущена в 0.18.0. Её не исправляют и к ней не возвращаются; совместимость с её файлами не нужна (чистая установка). Всё из PowerShell-версии перенесено; дальнейшие задачи — в `docs/roadmap.md`.

**Зависимости:**
- ядро работает без установки чего-либо на ПК: один бинарник;
- Go-модули — только MIT, BSD или Apache-2.0, без cgo, с версиями в `go.sum`; в PR указывай, зачем нужна новая зависимость. Версия Go — из `go.mod`; `golang.org/x/sys` не новее версии, совместимой с этой версией Go;
- Python, Node.js и другие программы на ПК допустимы только для необязательных возможностей (например, расширенный мониторинг): без них панель работает и показывает, что компонент не установлен;
- Docker, WSL и WinSW для работы ядра не требуются. Node используется в тесте интерфейса.

## Принципы, которые нельзя нарушать

1. **Минимальная нагрузка в простое.** Никаких фоновых таймеров опроса служб, GPU и моделей. Всё вычисляется по запросу пользователя или клиента; периодическая телеметрия — только при открытой вкладке и работающем движке; разовый снимок — по действию пользователя (вход, возврат на вкладку, «Обновить данные»). Исключение по решению владельца — расписание автоматизаций (`automations.Scheduler`): один таймер до ближайшего запуска, только пока у какой-то автоматизации включено расписание; переставляется при изменении автоматизаций и после запуска, без опроса; моделей не запускает.
2. **Модель выбирается в панели.** Запрос к API не может сам загрузить другую модель или запустить остановленный сервер. Любое автопереключение — только отдельной опцией, выключенной по умолчанию.
3. **Работа без API key разрешена.** Переключатель ключа сохраняется.
4. **После «Остановить» сервер остаётся остановленным** при любом восстановлении: откат, автоперезапуск, обновление.
5. **Одна модель и одна генерация одновременно.** Параллельные запросы ждут в очереди `/v1`, привязанной к поколению: после остановки или смены модели запрос из очереди не выполняется на другой модели.
6. **Обновление не теряет пользовательские данные:** пароль панели, API key, адреса NAS, `config.json`, модели. Любой сбой установки откатывается автоматически.

|---|---|

| `cmd/omnibox` | Точка входа: `serve`, `engine`, `version` |

| `internal/host` | Хост службы движка: Job Object (Windows) или группа процессов (Linux), журналы, `runtime.json` |

| `internal/automations` | Автоматизации: шаги (задача, поля, документ — последним), хранение, шаблоны и история (`automations/` в каталоге данных), проверки полей, поиск полей моделью, значения, готовые документы в памяти на час, расписание (`Scheduler`) |
| `internal/reasoning` | Профили размышлений моделей (выключаемые, всегда включённые, уровни, бюджет) и очистка неподдерживаемых параметров |
| `internal/websearch`, `internal/attach`, `internal/library` | SearXNG и чтение страниц (только публичные адреса); текст из .pdf/.docx/.xlsx/.csv; единый список локальных и облачных моделей |

| `web/` | Интерфейс панели: `app.js` (общее), `chat.js`, `projects.js` (проекты и временный чат), `models.js`, `server.js`, `settings.js`, `automations.js`. Оформление — по брендбуку `docs/brand/` и прототипу `docs/design/`. `web/vendor` — KaTeX, highlight.js, Mermaid без изменений (MIT/BSD-3, `LICENSES.txt`), загружаются только при надобности |

Программа не должна копить файлы на ПК: всё, что пишется на диск (журналы, временные файлы), имеет ротацию, срок хранения или удаление. Очистка — только при запуске службы, установке или по действию пользователя, без таймеров.

## Порядок работы

- **Ветки и PR.** Не коммить напрямую в `main`. Одна задача — одна ветка и pull request. Агент сам сливает свой PR (решение владельца): только при зелёном CI на Windows и Linux на последнем коммите, без конфликтов и неотвеченных замечаний ревью; PR только с документацией — после локального `go test .`. Способ слияния — обычный merge commit.
- **Коммиты:** `тип: описание`, где тип — `feat`, `fix`, `docs`, `test`, `ci`, `build`, `refactor`. К релизному коммиту допиши версию в скобках: `feat: ... (0.18.0)`.
- **Выпуск:** после слияния PR с новой версией агент сам запускает workflow **Release** из `main` (без «pre-release») и проверяет, что выпуск `v<VERSION>` опубликован; тег и файлы создаёт workflow, вручную агент их не создаёт. Устанавливает выпуск на серверный ПК владелец — кнопкой в панели или `ai update`.
- **Каждая пользовательская версия:** обнови `VERSION`, добавь раздел `## x.y.z — дата` в начало `CHANGELOG.md`, поправь `Версия **x.y.z**` в `README.md` и строку «Состояние на …» в `docs/roadmap.md`, добавь `### x.y.z` в «Выполнено по версиям». Иначе упадёт `TestVersionIsTheSingleSource`.
- **Документация:** при изменении поведения обнови `docs/` и `README.md`. Тексты для пользователя пишутся на русском.
- **План (`docs/roadmap.md`) обновляется в каждом PR — без исключений:**
  - сделанное запиши в «Выполнено по версиям» (для PR без новой версии — в запись текущей версии);
  - отметь выполненные или частично выполненные пункты в разделах 1–4;
  - новые задачи, найденные проблемы и решения владельца добавь в соответствующие разделы; устаревшее убери.
- **Объём изменений:** минимально необходимый для задачи; не переформатируй чужой код без нужды.

## Стиль кода

- Пиши как окружающий код: те же имена, плотность и идиомы. `gofmt` обязателен.
- **Языки:** сообщения пользователю (ошибки панели, вывод команд, UI) — на русском; ошибки `/v1` для клиентов — на английском в формате OpenAI; комментарии в коде и сообщения коммитов — на английском. Комментарий объясняет «почему», а не пересказывает код.
- **Платформы:** код для одной ОС — в файлах `*_windows.go` / `*_unix.go` за интерфейсом в `internal/platform` или своём пакете; сборка обеих ОС не должна ломаться (`GOOS=windows go vet ./...`).
- **Файлы:** настройки и состояние пиши через `platform.WriteAtomic`, читай через `platform.ReadShared` (на Windows читатель не мешает атомарной замене). `config.json` меняется только через `config.Store.Update`.
- **Окончания строк** задаёт `.gitattributes`: всё LF, кроме `.ps1`/`.cmd` (будущие скрипты установки для Windows PowerShell) — CRLF.
- **Интерфейс** следует брендбуку OMNIBOX (`docs/brand/README.md`, PDF рядом): палитра Void/Deep Night/Signal, акцент Iris, градиент Ice → Iris → Ember без смены порядка, без синего и мигания; логотип не растягивать и не перекрашивать. В вебе без CDN: шрифты и картинки лежат локально и встраиваются в бинарник.

## Безопасность

- Служба работает от SYSTEM (root на Linux). Нельзя добавлять маршруты, которые выполняют произвольные команды или читают произвольные файлы; маршруты и статика фиксированы, операции панели — структурированные поля, без командной строки.
- Изменяющие запросы требуют сессию, CSRF и проверку Origin/Host. `X-Forwarded-*` принимаются только от IP из `panel.trusted_proxies`.
- Ключ API проверяется до любых обращений к службам и движку.
- Содержимое запросов к `/v1` записывается только при явном выборе владельца (`storage.request_log: content`), в отдельный `content.jsonl`; по умолчанию — только метаданные.
- Автоматизации (`internal/automations`, решения владельца): на ПК хранятся сами автоматизации, их шаблоны и — только если владелец включил её в автоматизации — история результатов со сроком хранения чатов (`automations/` в каталоге данных, права только службы; удаление стирает шаблон и историю сразу). У конфиденциальной автоматизации истории нет никогда. Данные запуска (фото, файлы) приходят с запросом и не пишутся на диск; готовый документ — только в памяти службы, час. Инструменты — только поиск и чтение страниц чата, по выбору в автоматизации, в том числе по сайтам, которые владелец указал в шаге; новые — только по явному выбору владельца в автоматизации. Запросы автоматизаций, включая составление поисковых запросов, идут через `gateway.Automation` и никогда не попадают в `content.jsonl`. Режим «Конфиденциально» — только локальная модель, без поиска, истории и расписания — проверяется службой при сохранении и при каждом запуске, а не интерфейсом. Запуск по расписанию — действие владельца, заданное заранее: его исходящие соединения те же, что у ручного запуска этой автоматизации. Не ослабляй это.
- Исключение по решению владельца — чат панели: сообщения хранятся на ПК (`chats/` в каталоге данных, по файлу на чат, права только службы) со сроком хранения; закреплённые не удаляются по сроку. Удаление чата, сообщения или всех данных сразу стирает файлы, без корзины и копий. Изображения, аудио и видео из вложений не сохраняются.
- Временный чат (решение владельца) никогда не пишется на диск: он живёт в памяти службы, не попадает в список и поиск, удаляется, когда владелец уходит из него, забытый — через сутки (при следующем списке или новом временном чате, без таймера) или при перезапуске. Его запросы, включая служебные (название, вопросы для продолжения, поисковые запросы), идут через `gateway.Automation` и никогда не попадают в `content.jsonl`. Не ослабляй это.
- Проекты (решение владельца): на ПК хранятся проект (название, значок, указания) и только текст его документов (`projects/` в каталоге данных, права только службы), сами файлы — нет. Удаление документа, проекта или «Удалить все данные» стирает их сразу, без копий; `ai uninstall` удаляет каталог данных целиком. Документы передаются только модели чата этого проекта.
- Исходящие соединения службы — только по действию владельца или клиента и только туда, куда он указал: GitHub (выпуски), Hugging Face (каталог), openrouter.ai (ключ OpenRouter, в том числе поиск Perplexity Sonar), поисковая система из настроек — SearXNG владельца или API Perplexity, Tavily, Brave Search с ключом владельца (уходит только поисковый запрос, не переписка). Без редиректов на другие адреса. Исключение по решению владельца — чтение страниц веб-поиска (`websearch.Reader`): только адреса из результатов поиска и из вопроса, а у шага автоматизации с сайтами владельца (`Step.Sites`) — ещё любые страницы этих сайтов и ссылки между ними (поиск у такого шага — только по этим сайтам); только публичные IP (проверка при каждом соединении, в том числе после переадресации), с лимитами размера и времени. Второе исключение — Codex app-server для ChatGPT по подписке (`internal/chatgpt`): скачивается из выпусков `openai/codex` только по кнопке владельца, запускается службой по запросу чата или клиента `/v1` и соединяется только с OpenAI. Codex — только модель: его `config.toml` (пишется при каждом запуске) выключает инструменты, у тредов нет окружения (`environments: []`), встречные запросы Codex отклоняются, а ход с чем-либо кроме сообщения и размышлений прерывается. Единственное исключение по решению владельца — серверный веб-поиск OpenAI (`web_search`), включаемый для треда только по `web_search_options` и опции «Встроенный поиск OpenAI»: он выполняется на стороне OpenAI и ничего не делает на ПК. Не ослабляй это и не добавляй Codex других инструментов.
- Секреты (пароль, API key, токены) не попадают в журналы, ответы API, сообщения об ошибках и аргументы командной строки. Хранятся только hash (PBKDF2 для пароля, SHA256 для ключа). Исключение по решению владельца — GitHub token для обновлений из панели: служба работает от SYSTEM и не видит вход владельца в `gh`, поэтому токен хранится зашифрованным (DPAPI) в `run/github-token.bin`, используется только для выпусков GitHub, не возвращается в панель, удаляется кнопкой и при `ai uninstall`. Так же хранится ключ OpenRouter (`run/openrouter-key.bin`): используется только для запросов к openrouter.ai, не возвращается в панель (там — только последние 4 символа), удаляется кнопкой «Отключить и удалить ключ» и при `ai uninstall`. Так же хранятся ключи поисковых систем (`run/search-keys.bin`): используются только для своей системы, в панель — только конец ключа, удаляются кнопкой и при `ai uninstall`. Вход ChatGPT хранит сам Codex (`chatgpt/home/auth.json` в каталоге данных с правами только службы): OmniBox его не читает и не возвращает в панель; удаляется «Выйти из аккаунта», «Удалить Codex и вход» и при `ai uninstall`.
- Прокси `/v1` ходит только на loopback-адреса, без редиректов; ключ клиента не передаётся движку.
- Не ослабляй права на каталоги установки и правила Firewall без явной просьбы владельца.

## Тесты

Тесты — стандартный `go test` и `tests/web_test.cjs`. Службы ОС, движки и `nvidia-smi` в тестах заменяются адаптерами (`platform.FakeServices`, `httptest`-движки, тестовый бинарник как поддельный движок).

```sh
gofmt -l . ; go vet ./... ; GOOS=windows go vet ./... ; go test ./...
node tests/web_test.cjs
```

- Новое поведение покрывай тестом в пакете, который его реализует. Исправление ошибки — с тестом, который падал без исправления.
- Тест не должен зависеть от разделителя путей, окончаний строк checkout, сети, GPU или скачанной модели; конкурентный код проверяй с `-race`.
- Никогда не регистрируй настоящие службы в обычных тестах и не запускай тесты, меняющие службы, на серверном ПК пользователя.

## CI

`.github/workflows/ci.yml` запускается на каждое обновление pull request (и вручную); push в ветку и слияние в `main` его не запускают — минуты Actions ограничены, Windows считается вдвое. Новый push в тот же PR отменяет незавершённый прогон. PR только с документацией (`docs/`, `*.md`) CI не запускает: перед слиянием такого PR прогони `go test .` локально (проверка единой версии). Укрупняй изменения: меньше PR и выпусков, больше работы в каждом.

- **Windows** (`windows-latest`): `go vet`, `go test` (в том числе хост движка с Job Object), сборка `omnibox.exe`, разбор `install.ps1` и `scripts/remove-old-version.ps1` во встроенном Windows PowerShell 5.1.
- **Linux** (`ubuntu-latest`): `gofmt`, `go vet` для обеих ОС, `go test -race`, сборки для Linux и Windows без cgo, `web_test.cjs`, проверка синтаксиса `install.sh`.

Перед push прогони проверки локально. Красный CI — это работа, а не «флейк»: найди причину. Тесты нельзя отключать, пропускать или ослаблять ради зелёного CI.
